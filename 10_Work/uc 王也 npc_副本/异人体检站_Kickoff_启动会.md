## 📋 一页纸项目概览（Kick-off 核心信息）

### 一句话

> **8-9 周内交付「异人体检站」H5，让 300 万+ 预约用户通过王也 AI 体检完成裂变拉新 100 万+。**

### 项目参数

| 维度 | 数值 |
|------|------|
| **总工期** | 9 周（4 周开发 + 3 周测试 + 1 周内测 + 1 周缓冲） |
| **关键路径** | 5 周（Prompt 串行 2.5 周 → 全链路联调 → 测试） |
| **总人天** | 80-95 人天 |
| **团队规模** | 15-17 人（核心 7 + QA 6-7 + 运营 2） |
| **预算范围** | 280-500 万 |

### 核心产品

```
用户打开 H5 → 输入 ID/昵称（5秒）
    ↓
STEP 1: 王也批命吐槽 → 生成「批命卡」（可分享）
    ↓
STEP 2: 7 轮情景问诊（2分钟）→ 格斗画像 + 异人人格
    ↓
STEP 3: 王也出具「体检报告」（可分享长图）
    ↓
裂变: 朋友圈/微博/小红书 → 拉新 → 游戏预约
```

### 三个最大风险

| # | 风险 | 应对 |
|---|------|------|
| 🥇 | **"像不像王也"** — AI 输出质量决定项目成败 | 50 条金标准测试集 + IP 粉内测 + Prompt 5+ 版迭代 |
| 🥈 | **测试时间被压缩** — 开发延期吃掉测试排期 | 开发冻结硬门槛 + AI 质量测试 5 天不可压缩 |
| 🥉 | **混元资源** — K-V Cache 是性能命脉 | **Week 1 必须拿到正式承诺** |

## 📐 技术架构速览

```
┌──────────────────────────────────────────────────┐
│                    H5 前端                        │
│  落地页 → 对话UI(SSE) → 批命卡 → 报告长图 → 分享  │
└──────────────┬───────────────────────────────────┘
               │ HTTPS + SSE
┌──────────────▼───────────────────────────────────┐
│                 后端 API 层                        │
│  Stateless + HMAC签名 | 令牌桶30K QPM | 优先队列   │
├──────────────────────────────────────────────────┤
│  双链路路由                                        │
│  ├─ 离线链路（ES fuzzy → 预生成库，80% 命中目标）    │
│  └─ 实时链路（混元 TurboS + K-V Cache）             │
├──────────────────────────────────────────────────┤
│  安全四层                                          │
│  L1: Aho-Corasick 多模式匹配                       │
│  L2: 混元安全模型（批命同步/对话异步）               │
│  L3: 200+ 兜底回复库                               │
│  L4: 人工巡检 + WebSocket 实时告警                  │
├──────────────────────────────────────────────────┤
│  渲染服务                                          │
│  Puppeteer 集群(10-20台4C8G) → CDN 缓存7天         │
│  html2canvas 降级备选                               │
├──────────────────────────────────────────────────┤
│  3 Agent Workflow                                  │
│  Agent 1 批命 → Agent 2 问诊(7轮) → Agent 3 出报   │
│  （串行依赖，Prompt 需 2.5 周）                     │
└──────────────────────────────────────────────────┘
```

### 关键技术决策（已在评审中确认）

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 流式推送 | **SSE**（非 WebSocket） | 单向推送足够，更简单可靠 |
| 报告渲染 | **Puppeteer 服务端**（html2canvas 降级） | Android 兼容性 Critical 风险 |
| 模糊匹配 | **ElasticSearch fuzzy query**（非 Jaro-Winkler） | 百万级暴力计算不可行 |
| 状态管理 | **Stateless + HMAC 签名**（非 Session） | 水平扩展 + 无单点 |
| 载体 | **H5**（非小程序） | 分享链路更灵活 |
| 安全审核 | **批命同步 + 对话异步** | 避免 200-500ms 延迟叠加 |

Week 5 ──────────────────────────────────────────────────
│ 功能测试（5d）+ AI 质量测试 Round 1

Week 6 ──────────────────────────────────────────────────

Week 7 ──────────────────────────────────────────────────
│ IP 粉内测（50-100 核心粉 + 20-30 非 IP 粉对照）

Week 8 ──────────────────────────────────────────────────
│ Go/No-Go 决策会 ★ M6
│ 最终修复 + 回归验证

│ 正式上线 🚀 ★ M7 + KOL 首发

## 📋 Kick-off 会议议程（60 分钟）

| 时间 | 议题 | 主讲 | 产出 |
|------|------|------|------|
| 0-5min | 开场 & 项目背景 | PM | — |
| 5-15min | **产品方案速览**（漏斗 + 核心体验 + KPI） | 产品经理 | 团队理解一致 |
| 15-25min | **技术架构 & 关键决策**（SSE/Puppeteer/ES/安全） | 后端高级 | 技术方向确认 |
| 25-35min | **时间线 & WBS 过读**（关键路径 + 风险） | PM | 里程碑共识 |
| 35-45min | **Week 1 行动计划**（逐人确认任务） | PM | 每人知道第一周做什么 |
| 45-55min | **Q&A + 阻碍识别** | 全员 | 阻碍清单 |
| 55-60min | **总结 & 下一步** | PM | 站会时间确认、协作工具确认 |

### ⭐ Kick-off 必须达成的 5 个共识

1. **JSON Schema 是并行开发的前提** — Day 1-2 必须完成，Prompt 工程师 + 产品经理 + 后端高级联合定义
2. **混元资源必须 Week 1 锁定** — PM 负责约混元团队同步会，拿到 TurboS + K-V Cache + 安全模型的正式承诺
3. **代码冻结是硬门槛** — Week 4 末冻结，冻结后只修 bug；测试阶段不被开发延期吃掉
4. **日站会节奏** — 每日 10:00，15 分钟，"昨日/今日/阻碍"三段式
5. **变更流程生效** — 从今天起，任何新增需求必须走变更请求流程（评估影响→决策→记录）
