## 一、产品概述

### 1.1 背景

海克斯大乱斗是《英雄联盟》的特色对局模式，玩家在对局中需要在 **4个阶段**（S1/S2/S3/S4）分别选择海克斯符文（每次3张同等级随机符文，每张有1次刷新机会）。

AI Coach 是对局内的单向AI助手，通过右侧海克斯机器人在关键时刻主动推送信息，帮助玩家**理解机制、选对符文、感受游戏爽感**。

### 1.2 产品目标

| 目标 | 说明 |
|------|------|
| 降低入门门槛 | 帮助新手快速上手，看懂符文、选对符文 |
| 放大爽感 | 连胜时鼓励冒险，连败时帮稳住局面 |
| 简单可调 | 所有推荐参数可运营后台实时调整，无需发版 |

### 1.3 核心功能

玩家每次选符文时，AI Coach 对**当前3张候选符文**分别提供：

| 推荐要素 | 说明 |
|----------|------|
| **三分类Logo** | 👍推荐选取（绿色）/ 🤔值得考虑（黄色）/ 🔄建议刷新（灰色） |
| **标签** | 最佳拍档 / 潜力组合 / 强力单卡 / 娱乐（连胜专属） |
| **推荐话术** | 10~15字的核心推荐理由 |

> **关键设计原则**：每张符文独立评分，不做强制3选1分布——3张都好就都推荐，3张都差就都建议刷新。

### 1.4 选符文阶段说明

| 阶段 | 触发时机 | 说明 |
|------|----------|------|
| S1 | 开局 | 第一次选符文 |
| S2 | 7级 | 第二次选符文 |
| S3 | 11级 | 第三次选符文 |
| S4 | 15级 | 最后一次选符文 |

- 符文等级共三种：**白银、黄金、棱彩**
- 阶段与等级是独立概念，每个阶段出现的符文等级由游戏随机决定

## 三、客户端需求

> **面向**：客户端开发  
> **核心职责**：对局内展示推荐结果、上报上下文信息

### 3.1 推荐结果展示

#### 3.1.1 三分类Logo

当玩家进入选符文阶段，对当前3张候选符文分别展示推荐Logo：

| Logo | 图标 | 颜色 | 含义 |
|------|------|------|------|
| 推荐选取 | 👍 | 绿色 `#22c55e` | 强力推荐 |
| 值得考虑 | 🤔 | 黄色 `#eab308` | 可以考虑 |
| 建议刷新 | 🔄 | 灰色 `#9ca3af` | 建议使用刷新机会 |

**展示规则**：
- 每张符文上方/侧方展示对应Logo图标
- Logo图标由后端接口返回，客户端按字段渲染即可

#### 3.1.2 标签展示

| 标签 | 展示样式 | 展示条件 |
|------|----------|----------|
| 最佳拍档 | 橙色标签气泡 | 仅"推荐选取"Logo的符文展示 |
| 潜力组合 | 蓝色标签气泡 | 仅"推荐选取"Logo的符文展示 |
| 强力单卡 | 紫色标签气泡 | 仅"推荐选取"Logo的符文展示 |
| 娱乐 | 彩色标签气泡 | 仅连胜模式 + "推荐选取"Logo的符文展示 |

**展示规则**：
- 每个符文最多展示 **1个** 标签
- "值得考虑"和"建议刷新"的符文 **不展示** 标签
- 标签文案和颜色由后端接口返回

#### 3.1.3 推荐话术

- 在Logo/标签下方展示 *2行文字**，最多15字
- 话术内容由后端接口返回
- 所有三分类（推荐/考虑/刷新）均展示话术

### 3.2 信息上报

在玩家进入选符文阶段时，需上报以下信息给后端请求推荐结果：

| 字段                   | 类型              | 必填  | 说明                            |
| -------------------- | --------------- | :-: | ----------------------------- |
| `hero_id`            | string          |  是  | 当前英雄ID                        |
| `hero_name`          | string          |  是  | 当前英雄名称                        |
| `stage`              | int             |  是  | 当前阶段（1/2/3/4）                 |
| `candidate_augments` | array\<string\> |  是  | 当前3张候选符文ID                    |
| `selected_augments`  | array\<string\> |  是  | 前置阶段已选符文ID列表（S1传空）            |
| `augment_tier`       | string          |  是  | 当前符文等级（silver/gold/prismatic） |
| `win_streak`         | int             |  是  | 当前连胜数（0表示无连胜）                 |
| `lose_streak`        | int             |  是  | 当前连败数（0表示无连败）                 |
| `game_id`            | string          |  是  | 对局唯一ID                        |

### 3.3 交互时序

```
玩家进入选符文阶段
    ↓
客户端采集上下文（英雄、阶段、候选符文、已选符文、连胜连败）
    ↓
客户端调用后端推荐接口（传入上下文）
    ↓
后端返回3张符文的推荐结果（Logo + 标签 + 话术）
    ↓
客户端渲染展示
    ↓
玩家选择/刷新符文
    ↓
客户端上报埋点（推荐结果 + 玩家实际选择）
```

### 3.4 异常处理

| 异常场景        | 处理方式                         |
| ----------- | ---------------------------- |
| 推荐接口超时（>2s） | 不展示推荐信息，不阻塞选符文流程             |
| 推荐接口返回错误    | 不展示推荐信息，返回“思考”               |
| 英雄信息获取失败    | 上报空hero_id，后端使用兜底推荐（只考虑符文胜率） |

### 3.5 埋点需求

| 埋点事件                         | 触发时机     | 关键字段                                           |
| ---------------------------- | -------- | ---------------------------------------------- |
| `ai_coach_recommend_show`    | 推荐结果展示成功 | game_id, stage, hero_id, 3张符文的logo/tag/话术      |
| `ai_coach_recommend_click`   | 玩家选择符文   | game_id, stage, chosen_augment_id, chosen_logo |
| `ai_coach_recommend_refresh` | 玩家使用刷新   | game_id, stage, refreshed_augment_id           |
| `ai_coach_recommend_fail`    | 推荐展示失败   | game_id, stage, error_type                     |
| `ai_coach_select_time`       | 玩家选符文耗时  | game_id, stage, duration_ms                    |

## 六、算法需求

> **面向**：算法开发  
> **核心职责**：评分模型实现、标签判定、话术生成  
> **详细算法设计**：参见《海克斯大乱斗方案.md》

### 6.1 评分模型

#### 6.1.1 核心评分公式

> v3.3 变更：移除英雄纠偏分（对该英雄所有符文加减相同值，不影响排序结果）。

$$\text{最终得分} = \mathbf{w}^\top \cdot \mathbf{s} + \text{黑科技组合加成}$$

其中：

$$\mathbf{s} = \begin{pmatrix} \text{符文胜率分} \\ \text{符文选择率分} \\ \text{UGC评分分} \end{pmatrix}, \quad \mathbf{w} = \begin{pmatrix} W_{winrate} \\ W_{pickrate} \\ W_{ugc} \end{pmatrix}$$

- $\mathbf{w}^\top \cdot \mathbf{s} \in [0, 100]$（基础分）
- 黑科技组合加成 $\in [0, 20]$（**上限20分**，BLACKTECH_BONUS_CAP = 20）
- 连胜/连败差异通过**切换权重向量 $\mathbf{w}$** 实现（标准/连胜/连败三套 profile）

#### 6.1.2 连胜/连败三套权重

$$\mathbf{w}_{standard} = \begin{pmatrix} W_{wr}^{std} \\ W_{pr}^{std} \\ W_{ugc}^{std} \end{pmatrix}, \quad \mathbf{w}_{winning} = \begin{pmatrix} W_{wr}^{win} \\ W_{pr}^{win} \\ W_{ugc}^{win} \end{pmatrix}, \quad \mathbf{w}_{losing} = \begin{pmatrix} W_{wr}^{lose} \\ W_{pr}^{lose} \\ W_{ugc}^{lose} \end{pmatrix}$$

| 模式 | 胜率权重 | UGC权重 | 设计意图 |
|------|----------|---------|----------|
| 标准 | 中 | 中 | 均衡推荐 |
| 连胜 | ↓降低 | ↑提高 | 鼓励冒险，推黑科技/娱乐 |
| 连败 | ↑大幅提高 | ↓降低 | 稳住局面，推高胜率符文 |

> 三项权重恒等于 1.0，所有权重可在参数面板实时调整。

#### 6.1.3 黑科技组合加成

| 类型            | 数量        | 说明              |
| ------------- | --------- | --------------- |
| 英雄专属黑科技（最佳拍档） | **985 条** | S1-S4均生效，不受阶段限制 |
| 通用黑科技组合（潜力组合） | **23 个**  | 受阶段感知逻辑影响       |
|               |           |                 |

**阶段感知加分逻辑**：
- S1/S2：通用组合适配英雄 → 潜力组合标签 + 加分
- S3/S4 未成型：仅小幅加分，不给标签
- S3/S4 已成型（前面已选组合件）：最高加成 + 标签

**特殊规则（所有阶段均适用）：**
> 从 S2 起，一旦已选符文凑成黑科技组合，即使评分仅在「值得考虑」区间，直接升级为「推荐选取」，鼓励玩家坚持已成型组合路线。
> 一个是如果三张符文都是点赞，那就把min（分数）的降级为思考，
> 如果都是建议刷新那就把max（分数）的升级为思考，如果无刷新次，则不推荐该符文。

#### 6.1.4 需实现的算法模块

| 模块 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 基础分计算 | 英雄ID、符文ID、权重 $\mathbf{w}$ | 0~100分 | 三维度加权 |
| 黑科技组合匹配 | 英雄、符文、阶段、已选符文 | 0~20分 + 标签 | 含S2-S4升级规则 |
| 套装羁绊加成 | 符文、已选符文 | 0~N分 | `5 × 已有件数` |
| 标签判定 | 上述结果 | 标签枚举 | 优先级：最佳拍档>潜力组合>强力单卡>娱乐 |
| 自适应阈值 | 英雄×等级的全量分数 | 推荐/考虑/刷新阈值 | 分英雄×分等级 |
| 连胜娱乐调整 | 连胜状态、全量分数 | 调整后分数 | 降级弱推荐+提升娱乐 |
| Logo分类 | 分数、阈值 | 三分类 | 推荐/考虑/刷新 |

#### 6.1.5 离线预计算产出物

| 产出物        | 格式       | 内容                |
| ---------- | -------- | ----------------- |
| 英雄×符文评分表   | CSV/JSON | 全英雄×全符文的基础分+黑科技加成 |
| 分英雄×分等级阈值表 | JSON     | 每英雄每等级的推荐/考虑/刷新阈值 |
| 标签判定结果     | JSON     | 每英雄×每符文的标签 + 话术   |
| 黑科技组合索引    | JSON     | 便于运行时快速查询组合关系     |

### 6.2 推荐话术

| 标签类型      | 话术来源                  | 字数限制 |
| --------- | --------------------- | :--: |
| 最佳拍档      | 黑科技组合分析中的"黑科技原因"，AI润色 | ≤15字 |
| 潜力组合      | 通用组合的"机制协同"，AI润色      | ≤15字 |
| 强力单卡      | 第三方攻略描述 + UGC评论，AI润色  | ≤15字 |
| 娱乐        | 掌盟UGC热门评论润色           | ≤15字 |
| 值得考虑/建议刷新 | AI生成                  | ≤15字 |

> **重要**：话术需区别于符文卡牌本身的描述（游戏内已展示），提供额外补充信息。

## **AI Coach 推荐平台**

> **核心职责**：团队自建的运营参数配置 + 模拟推荐调试平台

### 4.1 参数运营后台

提供 Web 管理后台，运营人员可实时调整推荐参数，**无需发版**即可生效。

#### 4.1.1 参数配置面板

| 参数分组 | 包含参数 | 说明 |
|----------|----------|------|
| 权重配置 | 标准/连胜/连败三套权重 $\mathbf{w}=(W_{wr}, W_{pr}, W_{ugc})^\top$ | 各3个，共9个参数 |
| 黑科技参数 | BLACKTECH_BONUS_CAP = **20** | 加成上限 |
| 阈值参数 | TARGET/MIN/MAX_RECOMMEND_PER_LEVEL, REFRESH_BOTTOM_PERCENT | 推荐数量与刷新阈值 |
| 标签参数 | STRONG_CARD_TOP_PERCENT = 15.0 | 强力单卡判定 |
| 连胜调整 | WINNING_DEMOTE_PERCENT, ENTERTAINMENT_BOOST | 连胜娱乐逻辑 |

**交互要求**：
- 参数输入框需带合法性校验（如权重三项之和 = 1.0）
- 保存时展示变更 diff，二次确认后生效
- 支持参数修改历史记录查看
- 支持"恢复默认值"一键操作
