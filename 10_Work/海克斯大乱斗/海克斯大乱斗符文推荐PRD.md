## 一、产品概述

### 1.1 背景

海克斯大乱斗是《英雄联盟》的特色对局模式，玩家在对局中需要在 **4个阶段**（S1/S2/S3/S4）分别选择海克斯符文（每次3张同等级随机符文，每张有1次刷新机会）。

AI Coach 是对局内的单向AI助手，通过右侧海克斯机器人在关键时刻主动推送信息，同时在海克斯符文选择时向玩家提供符文选择的指导，帮助玩家**理解机制、选对符文、感受游戏爽感**。

### 1.2 产品目标

| 目标 | 说明 |
|------|------|
| 降低入门门槛 | 帮助新手快速上手，看懂符文、选对符文 |
| 放大爽感 | 连胜时鼓励冒险，连败时帮稳住局面 |
| 简单可调 | 所有推荐参数可运营后台实时调整，无需发版 |

### 1.3 核心功能

玩家每次选符文时，AI Coach 对**当前3张候选符文**分别提供：

| 推荐要素 | 说明 |
|----------|------|
| **三分类Logo** | 👍推荐选取（绿色）/ 🤔值得考虑（黄色）/ 🔄建议刷新（灰色） |
| **标签** | 最佳拍档 / 潜力组合 / 强力单卡 / 娱乐（连胜专属） |
| **推荐话术** | 10~15字的核心推荐理由 |

> **关键设计原则**：每张符文独立评分，不做强制3选1分布——3张都好就都推荐，3张都差就都建议刷新。

### 1.4 选符文阶段说明

| 阶段 | 触发时机 | 说明 |
|------|----------|------|
| S1 | 开局 | 第一次选符文 |
| S2 | 7级 | 第二次选符文 |
| S3 | 11级 | 第三次选符文 |
| S4 | 15级 | 最后一次选符文 |

- 符文等级共三种：**白银、黄金、棱彩**
- 阶段与等级是独立概念，每个阶段出现的符文等级由游戏随机决定

## 三、客户端需求

> **面向**：客户端开发  
> **核心职责**：对局内展示推荐结果、上报上下文信息

### 3.1 推荐结果展示

#### 3.1.1 三分类Logo

当玩家进入选符文阶段，对当前3张候选符文分别展示推荐Logo：

| Logo | 图标  | 颜色           | 含义       |
| ---- | --- | ------------ | -------- |
| 推荐选取 | 👍  | 绿色 `#22c55e` | 强力推荐     |
| 值得考虑 | 🤔  | 黄色 `#eab308` | 可以考虑     |
| 建议刷新 | 🔄  | 灰色 `#9ca3af` | 建议使用刷新机会 |

**展示规则**：
- 每张符文上方/侧方展示对应Logo图标
- 3张符文独立判定，可以出现"3个都推荐"或"3个都建议刷新"
- Logo图标由后端接口返回，客户端按字段渲染即可

#### 3.1.2 标签展示

| 标签   | 展示样式   | 展示条件                    |
| ---- | ------ | ----------------------- |
| 最佳拍档 | 橙色标签气泡 | 仅"推荐选取"Logo的符文展示        |
| 潜力组合 | 蓝色标签气泡 | 仅"推荐选取"Logo的符文展示        |
| 强力单卡 | 紫色标签气泡 | 仅"推荐选取"Logo的符文展示        |
| 娱乐   | 彩色标签气泡 | 仅连胜模式 + "推荐选取"Logo的符文展示 |

**展示规则**：
- 每个符文最多展示 **1个** 标签
- "值得考虑"和"建议刷新"的符文 **不展示** 标签
- 标签文案和颜色由后端接口返回

#### 3.1.3 推荐话术

- 在Logo/标签下方展示 **1行文字**，最多15字
- 话术内容由后端接口返回
- 所有三分类（推荐/考虑/刷新）均展示话术

### 3.2 上下文信息上报

客户端在玩家进入选符文阶段时，需上报以下信息给后端请求推荐结果：

| 字段                   | 类型              | 必填  | 说明                            |
| -------------------- | --------------- | :-: | ----------------------------- |
| `hero_id`            | string          |  是  | 当前英雄ID                        |
| `hero_name`          | string          |  是  | 当前英雄名称                        |
| `stage`              | int             |  是  | 当前阶段（1/2/3/4）                 |
| `candidate_augments` | array\<string\> |  是  | 当前3张候选符文ID                    |
| `selected_augments`  | array\<string\> |  是  | 前置阶段已选符文ID列表（S1传空）            |
| `augment_tier`       | string          |  是  | 当前符文等级（silver/gold/prismatic） |
| `win_streak`         | int             |  是  | 当前连胜数（0表示无连胜）                 |
| `lose_streak`        | int             |  是  | 当前连败数（0表示无连败）                 |
| `game_id`            | string          |  是  | 对局唯一ID                        |

### 3.3 交互时序

```
玩家进入选符文阶段
    ↓
客户端采集上下文（英雄、阶段、候选符文、已选符文、连胜连败）
    ↓
客户端调用后端推荐接口（传入上下文）
    ↓
后端返回3张符文的推荐结果（Logo + 标签 + 话术）
    ↓
客户端渲染展示
    ↓
玩家选择/刷新符文
    ↓
客户端上报埋点（推荐结果 + 玩家实际选择）
```

### 3.4 异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| 推荐接口超时（>2s） | 不展示推荐信息，不阻塞选符文流程 |
| 推荐接口返回错误 | 不展示推荐信息，静默降级 |
| 英雄信息获取失败 | 上报空hero_id，后端使用兜底推荐 |

### 3.5 埋点需求

| 埋点事件                         | 触发时机     | 关键字段                                           |
| ---------------------------- | -------- | ---------------------------------------------- |
| `ai_coach_recommend_show`    | 推荐结果展示成功 | game_id, stage, hero_id, 3张符文的logo/tag/话术      |
| `ai_coach_recommend_click`   | 玩家选择符文   | game_id, stage, chosen_augment_id, chosen_logo |
| `ai_coach_recommend_refresh` | 玩家使用刷新   | game_id, stage, refreshed_augment_id           |
| `ai_coach_recommend_fail`    | 推荐展示失败   | game_id, stage, error_type                     |

## 四、前端需求（模拟推荐后台）

> **面向**：前端开发  
> **核心职责**：运营参数配置后台 + 模拟推荐调试面板

### 4.1 参数运营后台

提供一个 Web 管理后台，运营人员可实时调整推荐参数，**无需发版**即可生效。

#### 4.1.1 参数配置面板

需展示以下参数分组，每组参数支持编辑 + 保存 + 恢复默认值：

| 参数分组 | 包含参数 | 参数数量 |
|----------|----------|:--------:|
| 权重配置 | 标准/连胜/连败三套权重（W_winrate, W_pickrate, W_ugc） | 9 |
| 归一化参数 | WR_FLOOR, WR_CEILING, PR_SATURATION, UGC_MAX | 4 |
| 黑科技参数 | BLACKTECH_BONUS_CAP | 1 |
| 英雄纠偏 | HERO_CORRECTION_STRENGTH, MAX, MIN | 3 |
| 阈值参数 | TARGET/MIN/MAX_RECOMMEND_PER_LEVEL, REFRESH_BOTTOM_PERCENT | 4 |
| 标签参数 | STRONG_CARD_TOP_PERCENT | 1 |
| UGC处理 | UGC_CLIP_PERCENTILE, UGC_BAYESIAN_PRIOR_WEIGHT | 2 |
| 连胜调整 | WINNING_DEMOTE_PERCENT, ENTERTAINMENT_BOOST | 2 |

**交互要求**：
- 参数输入框需带合法性校验（如权重三项之和 = 1.0）
- 保存时展示变更 diff，二次确认后生效
- 支持参数修改历史记录查看
- 支持"恢复默认值"一键操作

#### 4.1.2 固定阈值兜底配置

| 符文等级 | 推荐阈值 | 考虑阈值 |
|----------|:--------:|:--------:|
| 白银 | 42 | 28 |
| 黄金 | 45 | 30 |
| 棱彩 | 35 | 22 |

上述兜底阈值也需支持后台配置修改。

### 4.2 模拟推荐面板

提供调试用的模拟推荐面板，供产品/算法验证推荐效果。

#### 4.2.1 操作流程

```
选择连胜/连败状态 → 选择英雄 → 选择阶段 → 自动联动等级 → 选择/添加前置已选符文 → 查看推荐结果
```

#### 4.2.2 面板元素

| 元素 | 类型 | 说明 |
|------|------|------|
| 连胜/连败状态 | 下拉选择 | 标准 / 连胜(3+) / 连败(3+) |
| 英雄选择 | 搜索下拉 | 支持模糊搜索英雄名 |
| 阶段选择 | 单选按钮 | S1 / S2 / S3 / S4 |
| 符文等级 | 自动联动 | 根据阶段自动设定（S1→白银, S2→黄金, S3→黄金, S4→棱彩），支持手动覆盖 |
| 前置已选符文 | 多选下拉+随机模拟按钮 | S2需1张，S3需2张，S4需3张 |
| 推荐结果区 | 卡片列表 | 展示该英雄该等级下所有符文的 Logo + 标签 + 分数 + 话术 |

#### 4.2.3 结果展示

每个符文卡片需展示：
- 符文名称
- Logo图标（三分类）
- 标签（如有）
- 最终分数（调试用，线上不展示）
- 推荐话术
- 各维度子分数（胜率分、选率分、UGC分、黑科技加成，调试用）

**返回结构**：

```json
{
  "code": 0,
  "data": {
    "game_id": "xxx",
    "stage": 2,
    "mode": "standard",  // standard / winning / losing
    "recommendations": [
      {
        "augment_id": "Hextech_001",
        "augment_name": "缩小引擎",
        "logo": "recommend",        // recommend / consider / refresh
        "logo_color": "#22c55e",
        "tag": "潜力组合",           // 最佳拍档/潜力组合/强力单卡/娱乐/null
        "tag_color": "#3b82f6",
        "reason": "小身板高法强",    // 推荐话术，≤15字
        "score": 78.5               // 调试用，生产环境可选返回
      }
    ],
    "trace_id": "xxx"               // 用于效果回收追踪
  }

```

#### 5.1.2 性能要求

| 指标 | 要求 |
|------|------|
| 接口耗时 | P99 < 500ms |
| 超时降级 | 客户端2s超时，后端需在500ms内返回 |
| QPS | 预估峰值：单局4次调用 × 同时在线局数 |
| 可用性 | 99.9%，推荐失败时返回兜底结果 |

#### 5.1.3 兜底策略

| 场景 | 兜底方式 |
|------|----------|
| 英雄数据缺失 | 使用全局符文胜率 + 固定阈值 |
| 知识库加载失败 | 返回全部"值得考虑" + 无标签 |
| 算法计算异常 | 返回默认推荐（按全局胜率排序Top3） |

## 六、算法需求

> **面向**：算法开发  
> **核心职责**：评分模型实现、标签判定、话术生成  
> **详细算法设计**：参见《海克斯大乱斗方案.md》

### 6.1 评分模型

#### 6.1.1 核心评分公式

```
最终得分 = W^T(符文胜率分,符文选择率分,UGC评分) + 英雄胜率纠偏 + 黑科技组合加成
```

其中：
```
W =  [W_winrate, W_pickrate, W_ugc]
```

#### 6.1.2 需实现的算法模块

| 模块      | 输入             | 输出         | 说明                     |
| ------- | -------------- | ---------- | ---------------------- |
| 基础分计算   | 英雄ID、符文ID、权重配置 | 0~100分     | 三维度加权                  |
| 英雄纠偏    | 英雄胜率           | -5 ~ +8分   | 拉平英雄间差异                |
| 黑科技组合匹配 | 英雄、符文、阶段、已选符文  | 0~20分 + 标签 | 详见方案文档第三章              |
| 套装羁绊加成  | 符文、已选符文        | 0~N分       | `5 × 已有件数`             |
| 标签判定    | 上述结果           | 标签枚举       | 按优先级：最佳拍档>潜力组合>娱乐>强力单卡；强力单卡=胜率Top15% ∪ 选取率Top7绿通 |
| 自适应阈值   | 英雄×等级的全量分数     | 推荐/考虑/刷新阈值 | 分英雄×分等级                |
| 连胜娱乐调整  | 连胜状态、全量分数      | 调整后分数      | 降级弱推荐+提升娱乐             |
| Logo分类  | 分数、阈值          | 三分类        | 推荐/考虑/刷新               |

#### 6.1.3 离线预计算产出物

算法需离线产出以下数据，供后端服务加载：

| 产出物 | 格式 | 内容 |
|--------|------|------|
| 英雄×符文评分表 | CSV/JSON | 全英雄×全符文的基础分+黑科技加成 |
| 分英雄×分等级阈值表 | JSON | 每英雄每等级的推荐/考虑/刷新阈值 |
| 标签判定结果 | JSON | 每英雄×每符文的标签 + 话术 |
| 黑科技组合索引 | JSON | 便于运行时快速查询组合关系 |

### 6.2 推荐话术

| 标签类型 | 话术来源 | 字数限制 |
|----------|----------|:--------:|
| 最佳拍档 | 黑科技组合分析V5中的"黑科技原因"，AI润色 | ≤15字 |
| 潜力组合 | 通用黑科技组合的"机制协同"，AI润色 | ≤15字 |
| 强力单卡 | 第三方攻略描述 + UGC评论，AI润色 | ≤15字 |
| 娱乐 | 掌盟UGC热门评论润色 | ≤15字 |
| 值得考虑 | 简要生成推荐理由 | ≤15字 |
| 建议刷新 | 委婉劝玩家刷新 | ≤15字 |

> **重要**：话术需区别于符文卡牌本身的描述（游戏内已展示），提供额外补充信息。

## 七、数据需求

> **面向**：数据开发  
> **核心职责**：取数、知识库维护、数据质量监控

### 7.1 数据源清单

| # | 数据类型 | 文件名 | 关键字段 | 更新频率 | 用途 |
|---|----------|--------|----------|----------|------|
| D1 | SQL取数 | step1_1_augment_stats.csv | win_rate, show_rate | 每日/每周 | 全局符文胜率（兜底） |
| D2 | SQL取数 | step1_2_champion_augment_stats.csv | win_rate, show_rate | 每日/每周 | 英雄×符文胜率（核心） |

### 7.2 数据质量要求

| 检查项 | 规则 | 处理 |
|--------|------|------|
| 英雄×符文胜率缺失 | 某英雄缺失符文胜率数据 | 回退到全局符文胜率 |
| UGC评分缺失 | 某符文无UGC评分 | 默认50分（中性） |
| 符文ID映射缺失 | ID找不到对应中文名 | 日志告警 + 使用ID作为展示名 |
| 数据时效 | CSV数据超过7天未更新 | 告警通知 |

### 7.3 知识库上传
