## 一、产品概述

### 1.1 产品定位

AI Coach 是海克斯大乱斗对局内的单向 AI 助手，在 **S1-S4 四个符文选择阶段**通过右侧海克斯机器人主动推送符文推荐，帮助玩家快速决策。

> 注意：选人阶段不触发符文推荐，推荐仅在对局内 S1-S4 阶段触发。

核心输出三要素：

| 输出 | 说明 |
|------|------|
| 三分类 Logo | 👍推荐选取 / 🤔值得考虑 / 🔄建议刷新 |
| 四类标签 | 最佳拍档 / 潜力组合 / 强力单卡 / 娱乐（连胜专属） |
| 推荐话术 | ≤15字推荐理由，区别于符文本身描述 |

### 1.2 设计原则

- 每张符文独立评分，不做强制 3 选 1
- 连胜鼓励冒险（黑科技/娱乐），连败帮稳局面（高胜率）
- 所有参数可在推荐平台实时调整

## 二、功能需求总览

### 2.1 推荐触发时机

| 阶段      | 触发条件 | 说明               |
| ------- | ---- | ---------------- |
| S1（2-1） | 进入阶段 | 基础符文推荐           |
| S2（3-1） | 进入阶段 | 动态调整 + 黑科技升级规则生效 |
| S3（4-1） | 进入阶段 | 动态调整 + 黑科技升级规则生效 |
| S4（5-1） | 进入阶段 | 最终推荐 + 黑科技升级规则生效 |

### 2.2 三分类 Logo

| Logo | 含义 |
|------|------|
| 👍 推荐选取 | 强烈推荐，优先选择 |
| 🤔 值得考虑 | 可以选择 |
| 🔄 建议刷新 | 建议使用刷新机会 |

| 标签   | 含义               | 优先级   |

| 强力单卡 | 该英雄胜率 Top15%     | 4     |

## 三、客户端需求

## 三、客户端需求

> **面向**：客户端开发  
> **核心职责**：对局内展示推荐结果、上报上下文信息

### 3.1 推荐结果展示

#### 3.1.1 三分类Logo

当玩家进入选符文阶段，对当前3张候选符文分别展示推荐Logo：

| Logo | 图标  | 颜色           | 含义       |
| ---- | --- | ------------ | -------- |
| 推荐选取 | 👍  | 绿色 `#22c55e` | 强力推荐     |
| 值得考虑 | 🤔  | 黄色 `#eab308` | 可以考虑     |
| 建议刷新 | 🔄  | 灰色 `#9ca3af` | 建议使用刷新机会 |

**展示规则**：
- 每张符文上方/侧方展示对应Logo图标
- 3张符文独立判定，可以出现"3个都推荐"或"3个都建议刷新"
- Logo图标由后端接口返回，客户端按字段渲染即可

#### 3.1.2 标签展示

| 标签   | 展示样式   | 展示条件                    |
| ---- | ------ | ----------------------- |
| 最佳拍档 | 橙色标签气泡 | 仅"推荐选取"Logo的符文展示        |
| 潜力组合 | 蓝色标签气泡 | 仅"推荐选取"Logo的符文展示        |
| 强力单卡 | 紫色标签气泡 | 仅"推荐选取"Logo的符文展示        |
| 娱乐   | 彩色标签气泡 | 仅连胜模式 + "推荐选取"Logo的符文展示 |

**展示规则**：
- 每个符文最多展示 **1个** 标签
- "值得考虑"和"建议刷新"的符文 **不展示** 标签
- 标签文案和颜色由后端接口返回

#### 3.1.3 推荐话术

- 在Logo/标签下方展示 **1行文字**，最多15字
- 话术内容由后端接口返回
- 所有三分类（推荐/考虑/刷新）均展示话术

### 3.2 上下文信息上报

客户端在玩家进入选符文阶段时，需上报以下信息给后端请求推荐结果：

| 字段                   | 类型              | 必填  | 说明                            |
| -------------------- | --------------- | :-: | ----------------------------- |
| `hero_id`            | string          |  是  | 当前英雄ID                        |
| `hero_name`          | string          |  是  | 当前英雄名称                        |
| `stage`              | int             |  是  | 当前阶段（1/2/3/4）                 |
| `candidate_augments` | array\<string\> |  是  | 当前3张候选符文ID                    |
| `selected_augments`  | array\<string\> |  是  | 前置阶段已选符文ID列表（S1传空）            |
| `augment_tier`       | string          |  是  | 当前符文等级（silver/gold/prismatic） |
| `win_streak`         | int             |  是  | 当前连胜数（0表示无连胜）                 |
| `lose_streak`        | int             |  是  | 当前连败数（0表示无连败）                 |
| `game_id`            | string          |  是  | 对局唯一ID                        |

### 3.3 交互时序

```
玩家进入选符文阶段
    ↓
客户端采集上下文（英雄、阶段、候选符文、已选符文、连胜连败）
    ↓
客户端调用后端推荐接口（传入上下文）
    ↓
后端返回3张符文的推荐结果（Logo + 标签 + 话术）
    ↓
客户端渲染展示
    ↓
玩家选择/刷新符文
    ↓
客户端上报埋点（推荐结果 + 玩家实际选择）
```

### 3.4 异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| 推荐接口超时（>2s） | 不展示推荐信息，不阻塞选符文流程 |
| 推荐接口返回错误 | 不展示推荐信息，静默降级 |
| 英雄信息获取失败 | 上报空hero_id，后端使用兜底推荐 |

### 3.5 埋点需求

| 埋点事件                         | 触发时机     | 关键字段                                           |
| ---------------------------- | -------- | ---------------------------------------------- |
| `ai_coach_recommend_show`    | 推荐结果展示成功 | game_id, stage, hero_id, 3张符文的logo/tag/话术      |
| `ai_coach_recommend_click`   | 玩家选择符文   | game_id, stage, chosen_augment_id, chosen_logo |
| `ai_coach_recommend_refresh` | 玩家使用刷新   | game_id, stage, refreshed_augment_id           |
| `ai_coach_recommend_fail`    | 推荐展示失败   | game_id, stage, error_type                     |

## 六、算法需求

### 6.1 评分公式（向量化）

> v3.3 变更：移除英雄纠偏分（对该英雄所有符文加减相同值，不影响排序）。

$$\text{最终得分} = \mathbf{w}^\top \cdot \mathbf{s} + \text{黑科技组合加成}$$

其中：

$$\mathbf{s} = \begin{pmatrix} \text{符文胜率分} \\ \text{符文选择率分} \\ \text{UGC评分分} \end{pmatrix}, \quad \mathbf{w} = \begin{pmatrix} W_{winrate} \\ W_{pickrate} \\ W_{ugc} \end{pmatrix}$$

$$\text{基础分} = \mathbf{w}^\top \cdot \mathbf{s} \in [0, 100]$$

### 6.2 连胜/连败机制（三套权重向量切换）

连胜/连败差异**通过切换权重向量 $\mathbf{w}$ 实现**，共三套 profile：

$$\mathbf{w}_{standard} = \begin{pmatrix} W_{wr}^{std} \\ W_{pr}^{std} \\ W_{ugc}^{std} \end{pmatrix}, \quad \mathbf{w}_{winning} = \begin{pmatrix} W_{wr}^{win} \\ W_{pr}^{win} \\ W_{ugc}^{win} \end{pmatrix}, \quad \mathbf{w}_{losing} = \begin{pmatrix} W_{wr}^{lose} \\ W_{pr}^{lose} \\ W_{ugc}^{lose} \end{pmatrix}$$

| 模式 | 胜率权重 | 选率权重 | UGC权重 | 设计意图 |
|------|----------|----------|---------|----------|
| 标准 | 中 | 中 | 中 | 均衡推荐 |
| 连胜 | ↓降低 | 保持 | ↑提高 | 鼓励冒险，推黑科技/娱乐 |
| 连败 | ↑大幅提高 | 保持 | ↓降低 | 稳住局面，推高胜率符文 |

> 三项权重恒等于 1.0，所有权重可在参数面板实时调整。

### 6.3 黑科技组合加成

**组合库**：23 个通用组合 + 985 条英雄专属 = 1,008 条

**加成上限**：**20 分**（BLACKTECH_BONUS_CAP = 20），多组合重叠取最高值不叠加

**阶段感知逻辑**：
- S1/S2：通用组合适配英雄 → 潜力组合标签 + 加分
- S3/S4 未成型：仅小幅加分，不给标签
- S3/S4 已成型（前面阶段已选组合件）：最高加成 + 标签
- 英雄专属：S1-S4 均生效，不受阶段限制

**S2-S4 黑科技升级规则（v3.3 新增）**：

> S2 起，一旦已选符文凑成黑科技组合，即使评分仅在「值得考虑」区间，直接升级为「推荐选取」。鼓励玩家坚持已成型组合路线。

### 6.4 自适应阈值

- 分英雄×分等级计算阈值，确保每个英雄都有推荐
- 目标：每英雄每等级约 4 个推荐选取
- 无英雄信息时使用固定阈值兜底

### 6.5 标签可见性

- 仅「推荐选取」Logo 的符文展示标签
- 标准模式下娱乐标签不展示，连胜模式下展示
- 推荐选取中最佳拍档+潜力组合不足 3 个时，补充强力单卡（最多 2 个）

### 6.6 娱乐标签（连胜≥3 触发）

- 最佳拍档/强力单卡按分数后 50% 施加负惩罚 → 降级
- 娱乐符文池符文施加 +15 分奖励 → 提升到推荐选取
- 重新排序和判定 Logo

## 附录A：兜底策略与异常处理

| 场景 | 兜底策略 |
|------|----------|
| 英雄数据缺失 | 使用全英雄平均符文胜率 |
| 黑科技组合库加载失败 | 跳过加成，仅用基础分推荐 |
| 接口超时（>2s） | 客户端展示缓存结果 |
| 推荐结果为空 | 返回该英雄热门符文 Top5 |
| 连胜连败数据异常 | 使用标准权重向量 |
| 新英雄无数据 | 同类型英雄平均数据冷启动 |

降级链路：`完整推荐 → 无黑科技推荐 → 缓存结果 → 热门符文兜底 → 默认推荐`
