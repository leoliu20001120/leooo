**四个关键判断**：

1. **PRD 排期低估 20-40%** — 技术评审确认前端 +2-4 天、后端 +2-4 天、Prompt +2-4 天，总工程量从 ~45 人天上调至 54-65 人天
2. **测试严重不足是最大盲区** — QA 评审指出"联调 4 天 + 内测 3 天"无法覆盖 AI 质量测试（5 天）、安全测试（3 天）、压测（3 天）、兼容性（2 天）、扩展内测（5 天），建议 15-18 天

4. **总工期建议调整为 8-9 周** — 5 周关键路径 + 3 周测试（部分与开发并行）+ 1 周缓冲

## 一、项目章程

### 1. 项目概述

#### 问题陈述

《一人之下》手游预约量已破 **2500 万**，但公测前面临三个核心问题：
- **沉默用户激活难**：大量预约用户"点了就忘"，需要重新唤醒
- **情感连接缺失**：格斗游戏的核心用户关注操作手感，IP 用户关注角色魅力，两类人群需求割裂
- **自然裂变不足**：从预约用户向泛游戏/泛国漫圈扩散缺少传播载体

#### 项目目标

在公测前 8~4 周，通过「王也 AI 体检站」H5 活动，让预约玩家在 **3 分钟**内完成一次"被王也读懂"的体验，产出**两份社交分享物**（批命卡 + 体检报告），实现**自传播裂变 + 预约转化**。

#### 范围

**✅ 包含（In Scope）**：
- 落地页 + ID 批命（STEP 0-1）
- 7 轮情景对话（STEP 2）
- 完整体检报告生成（STEP 3）
- 批命卡 + 体检报告两份分享物
- 3 个 AI Agent（批命/问诊/出报）+ Prompt 工程
- 格斗知识库（130+ 条）
- 离线预生成管线（100 万+ 热门 ID）
- 四层安全防护系统
- H5 前端全链路（落地页 → 对话 → 报告 → 分享）
- 后端 API（对话状态 + 双链路 + 限流）
- KOL 首发 + 话题运营 + 朋友圈广告
- IP 粉内测（50-100 人）

**❌ 不包含（Out of Scope）**：
- 开放式闲聊功能
- 游戏内功能/客户端集成
- 多角色（冯宝宝/张楚岚等）
- 每日算命完整功能（仅预埋入口）
- AI 语音/TTS
- 第二阶段（论道天下/入世之约）
- 第三阶段（游戏内 AI NPC）

#### 成功标准

| 指标 | 目标 | 优先级 | 底线 |
|------|------|--------|------|
| 输入 ID 总人数 | 300 万+ | P0 | 200 万 |
| 浅→深转化率（ID → 体检） | ≥ 60% | P0 | ≥ 50% |
| 体检完成率 | ≥ 80% | P0 | ≥ 70% |
| 分享率（批命卡 or 报告） | ≥ 30% | P0 | ≥ 20% |
| 裂变系数 K-factor | ≥ 1.5 | P1 | ≥ 1.2 |
| 新增预约数 | 100 万+ | P1 | 50 万 |
| 非负评率（安全） | ≥ 95% | P0 | ≥ 93% |
| 按时上线 | T-4 周准时 | P0 | 延迟 ≤ 3 天 |

### 3. 关键路径分析（~~4 周~~ → **5 周**，Tech Lead 确认）

**关键路径（最长依赖链）**：

```
知识库压缩(2d) → Agent1(3d) → Agent2(4-5d) → Agent3+联调(4d) = Prompt 串行 13-14d（~2.5 周）
                                                                    ↓
                                                            全链路联调(5-7d) → 测试阶段(15-18d)
                                                                    ↑
                        视觉设计(5-7d) → 前端开发(12-14d) → 联调 ──┘
                                         后端+安全(13-15d) → 联调 ──┘
```

**关键路径总长**：约 33-38 个工作日（6.6-7.6 周），加上缓冲 = **9 周**

**Tech Lead 核心论证（v2.0 新增）**：
1. **Prompt 工程不能完全并行**：Agent 2 依赖 Agent 1 的输出格式，Agent 3 依赖 1+2。串行至少 **2.5 周**（非 PRD 假设的 1.8 周）
2. **联调被低估**：3 个 Agent 串联 + 前后端对接 + 安全层 + **ES fuzzy query** + 报告渲染服务 = 至少 **5-7 天**（非 4 天）
3. **测试严重不足**：QA 评审指出 AI 质量测试（5d）+ 安全测试（3d）+ 压测（3d）是**不可压缩**的，因为 AI 输出无法完全自动化验证
4. **内测迭代需要时间**：IP 粉内测反馈"不像王也"→ Prompt 迭代 → 回归测试，一轮至少 **3 天**

#### 建议 3：🔴 测试不是开发的附属品 — 给 QA 独立的排期和资源 🆕

> 这是 v2.0 最重要的新增建议。

QA Lead 的评审揭示了一个核心矛盾：**AI 营销活动的测试复杂度远超传统 H5，但 PRD 给测试的时间仍按传统 H5 分配**。

具体措施：
- **测试阶段独立排期**（Week 5-7，共 3 周），不与开发阶段共享
- **开发冻结门槛**：Week 4 末代码冻结，冻结后只修 bug，不加新功能
- **AI 质量测试 5 天不可压缩** — 100+ ID 的人设打分无法自动化，必须人工评审
- **安全测试前置到 Week 3** — 脏词库 + 敏感人名库在开发中期即可验证，不等联调
- **QA 在 Week 3 开始编写测试用例** — 不等到 Week 5 才介入

#### 建议 4：🟡 技术方案变更需立即落实 🆕

Tech Lead 评审识别了 3 个需要立即变更技术方案的点：
1. **模糊匹配**：Jaro-Winkler → ElasticSearch fuzzy query（百万级数据暴力计算不可行）
2. **报告渲染**：html2canvas → Puppeteer 服务端渲染（Android 兼容性 Critical 风险）
3. **安全审核**：全同步 → 批命同步 + 对话异步（避免 200-500ms 延迟叠加）

这 3 个变更影响后端架构，需在 Week 1 技术方案评审会上确认并纳入工作量。

#### 建议 5：🟡 设定清晰的 Go/No-Go 标准，避免带伤上线

在 Week 8 末的 Go/No-Go 决策会上，必须满足以下条件才能上线：

| 条件 | 标准 | 否决权 | v2.0 变更 |

## 附录 B：变更请求流程

```
发起人提出变更
    │
    ▼
PM 登记到变更日志
    │
    ▼
评估影响（范围/时间/成本）
    │
    ├── 影响 ≤ 1 人日 → PM 审批 → 执行
    │
    ├── 影响 1-3 人日 → PM + 产品经理审批 → 执行
```
