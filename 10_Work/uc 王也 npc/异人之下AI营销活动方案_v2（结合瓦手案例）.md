## 1. 活动定位

### 一句话

> **"让 2500 万预约玩家在公测前就认识王也、被王也记住"**

### 核心差异化（vs 瓦手案例）

| 维度 | 瓦手AI放号官 | 瓦手秀ID | **我们：异人体检报告** |
|------|-------------|---------|---------------------|
| 核心驱动 | 功能（拿资格） | 功能（抢 ID） | **情感（被王也读懂）** |
| AI 人设 | 靶场机器人 | 靶场机器人 | **王也（道家冷幽默）** |
| 用户投入 | 6 轮对话 | 输入 ID | **5 秒 ID → 7 轮对话（渐进式）** |
| 产出物 | 面试评语 | 点评卡片 | **批命卡 + 完整体检报告（双分享物）** |
| 留存钩子 | 无 | 无 | **每日算命（日活留存）** |
| IP 知识库 | 1500 条 | 1500 条 | **1125+ 条 + 28 种场景回复** |

**我们的核心优势**：
1. **IP 情感浓度更高** — 王也是国漫顶流角色，用户跟他聊天有"追星"属性，瓦手的靶场机器人只是功能性
2. **双层漏斗 + 双分享物** — 瓦手两次活动是独立的，我们融合成一个渐进式体验
3. **留存闭环** — 瓦手是一次性活动，我们加了"每日算命"做日活留存

### vs 瓦手的进化点

| 维度 | 瓦手做法 | 我们的进化 |

| **入口门槛** | 秀 ID 只有输入名字 / 放号官直接 6 轮 | 先 5 秒体验（ID 点评）→ 再 2 分钟（深度问答），**漏斗式降低门槛** |

| **数据漏斗** | 单一指标 | 曝光 → 输入 ID → 转化体检 → 完成 → 分享 → 裂变新用户，**全链路可度量** |

## 3. Agent 技术方案（借鉴瓦手架构）

### 3.1 整体架构：Workflow 模式（非 Agentic）

> 瓦手的核心经验：**用 Workflow 代替 Agentic，确保低成本和高鲁棒性**。
> 我们照搬这个思路，用 3+1 个 Agent 协同：

```
┌──────────────────────────────────────────────────────────┐
│                   王也 AI Agent 架构                       │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  ┌─────────────┐   ┌─────────────┐   ┌──────────────┐  │
│  │  Agent 1     │   │  Agent 2     │   │  Agent 3      │  │
│  │  批命 Agent  │   │  问诊 Agent  │   │  出报 Agent   │  │
│  │              │   │              │   │               │  │
│  │ 输入：ID     │   │ 输入：7轮    │   │ 输入：ID评语   │  │
│  │ 输出：吐槽   │→→→│ 对话记录     │→→→│ + 7轮对话     │  │
│  │ + 星级       │   │ 输出：性格   │   │ 输出：完整     │  │
│  │              │   │ 向量+标签    │   │ 报告 JSON     │  │
```

### 3.2 双链路（高并发方案）

> 瓦手的核心经验：**80 万热门昵称预生成 + 实时推理双链路分流**，确保 7 秒内响应。

我们的方案：

| 链路 | 触发条件 | 响应时间 | 场景 |
|------|---------|---------|------|
| **离线预生成** | 热门昵称命中（百万级 ID 库）| < 1 秒 | STEP 1 批命（常见名字/网名） |
| **实时推理** | 未命中预生成库 | < 5 秒 | STEP 1 批命（个性化名字）+ STEP 2 全部对话 |

**离线库构建**：
- 从游戏预约数据提取 Top 100 万热门昵称
- 每个昵称预生成 3 条不同吐槽 + 星级（避免同名用户看到一样的）
- 用模糊匹配算法（Jaro-Winkler，参考瓦手）实现相似名字复用

### 3.3 知识库工程

> 瓦手用了 1500+ 条游戏术语/梗文化知识库。我们的优势：**已有 1125+ 条 + 28 种场景回复模板**。

**Prompt 结构**（参考瓦手 13K token 注入方式）：

```
[系统 Prompt ~15K token]
├── 角色设定：王也人设（道家视角、嘴损但不恶毒、冷幽默）
├── 知识库核心：1125+ 条精选 → 压缩到关键 500 条（按场景分组）
│   ├── 自我介绍（身份/武当/风后奇门）
│   ├── 世界观（甲申之乱/全性/天师府）
│   ├── 人物关系（冯宝宝/张楚岚/诸葛青）
│   ├── 修行哲学（道/无为/入世出世）
│   └── 网络梗/年轻化表达
├── 安全规则：禁止输出 + 边界约束
└── 输出格式：JSON Schema（批命/对话/报告三种模式）
```

**K-V Cache 策略**：
- 固定 Prompt（15K token）全局缓存，每个请求只需处理用户输入部分
- 参考瓦手：缓存复用 → 单实例 QPM 从 100 提升到 3000+

### 3.4 模型选择

| 选项 | 效果 | 成本 | 推荐 |
|------|------|------|------|
| 混元 TurboS | 验证过的效果（瓦手实战）| 低（资源占用比 DeepSeek 低 44 倍）| ✅ **首选** |
| 混元 Standard | 更强的长文生成 | 中 | 备选（报告生成用） |

## 4. 七个情景问答设计（STEP 2 详细设计）

> 参考 AI 放号官的 6 轮对话设计，但我们不是"面试"，是"王也跟你聊天"。

### 设计原则（从瓦手学到的）

1. **前 2 轮宽松**（简单问题，降低弃出率）→ 后 5 轮深入
2. **AI 动态追问**，不是固定脚本（用户感觉"王也真的在听"）
3. **每个回答都有即时反馈**（王也的一句话回应），保持互动感

### 问答详细设计

| # | 问题 | 测量维度 | 王也追问示例 | 深度 |
|---|------|---------|-------------|------|
| 1 | "你走在路上，突然看到有人头顶冒出奇怪的光，你会？" | 应激反应 | 选"跑" → "跑得倒是快，练过？" | 浅 |
| 2 | "如果有了异能，第一件事做什么？" | 价值观 | 选"赚钱" → "俗，但诚实。" | 浅 |
| 3 | "王也邀你入武当修行，三年不能下山。你？" | 耐性 | 选"不去" → "聪明人。但聪明不一定走得远。" | 中 |
| 4 | "甲申之乱中，师兄叛变了。你怎么办？" | 忠义观 | 选"杀" → "杀伐果断，但你确定他是叛变？" | 深 |
| 5 | "实力和心性，哪个更重要？" | 修行哲学 | 任选 → "两个都重要，但你的回答暴露了你缺哪个。" | 深 |
| 6 | "你更怕孤独，还是更怕被人围着？" | 性格底色 | 选"孤独" → "那你不适合修道。这条路很长，也很安静。" | 深 |
| 7 | "最后，给自己三个字的评价。" | 自我认知 | 开放题 → AI 综合前 6 题分析是否跟自评一致 | 核心 |

## 11. 核心创新点总结

| # | 创新点 | 对比瓦手的进化 |
|---|--------|--------------|
| 1 | **漏斗式体验**：5 秒浅入口 → 2 分钟深体验 → 完整报告 | 瓦手两次活动是独立的，我们融合成渐进式漏斗 |

| 4 | **留存闭环**：体检报告底部 → 每日算命 → 日活工具 | 瓦手是一次性活动，无留存设计 |
| 5 | **IP 情感浓度**：王也 = 国漫顶流角色，用户有"追星"心理 | 瓦手靶场机器人只是功能性 |
