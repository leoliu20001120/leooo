> **用真实游戏数据引发共鸣 → AI 千人千猫造梗 → 1v1 互损 PK 驱动裂变**，让每个玩家的峡谷人生都变成一只独一无二的猫。

## 1. 问题陈述

### 用户痛点

LOLM 手游的传统数据报告型活动（赛季总结、年度回顾）存在三个核心问题：

1. **同质化严重**：所有人拿到的报告模板一样，只是数字不同，缺乏个性化记忆点，难以驱动自发分享
2. **社交属性弱**：报告是单人体验，看完即走，缺乏「我和朋友一起玩」的裂变钩子
3. **情绪价值低**：冷冰冰的数据罗列（KDA、胜率），不造梗、不整蛊、不产生社交货币

### 机会

用「全员变猫」的世界观包装 + AI 千人千猫生成 + 1v1 好友 PK 互损机制，将数据报告从「看一眼就关」升级为「看完想分享、想 @好友、想拉人组队」的社交裂变引擎。

### 为什么是现在

- 猫 meme 文化持续高热（互联网流量密码）
- AI 生成图片技术成熟，千人千猫可实现
- LOLM 活跃期需要低成本高传播的社交营销工具
- H5 形态轻量，可快速验证

## 3. 非目标（明确不做什么）

- ❌ **不做群组队裂变** — 复杂度高、转化链路长，主打好友 1v1 单对单互动
- ❌ **不做游戏内嵌入** — 本期为独立 H5，不改动游戏客户端
- ❌ **不做英雄 cosplay 猫** — 猫咪不会完全还原英雄造型（不穿英雄同款服装、不拿英雄武器），只提取英雄的**标志性色彩/纹样/小配饰**作为猫咪的视觉点缀，保持猫咪本体的自然感，避免突兀和 IP 版权审核风险
- ❌ **不做复杂测试题** — 问卷控制在 3-5 题，追求流畅体验
- ❌ **不做实物周边兑换** — 本期不涉及实物物流

## 5. 解决方案概述

### 5.1 世界观包装

**「哈气咪宇宙」**：一个赛博萌系的喵星人世界观。所有界面使用猫咪视觉元素（猫爪光标、猫耳UI组件、喵呜音效），但生成的猫种与峡谷 IP 角色无关——纯粹是 AI 根据玩家数据创造的独一无二的猫。

### 5.2 核心玩法流程

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  阶段一 → 阶段二 → 阶段三 → 阶段四 → 阶段五               │
│  沉浸引入   喵格测试   AI加载     猫格档案    传播裂变       │
│  (~5s)     (~40s)    (~3s)     (核心产出)   (增长引擎)      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

### 阶段一：沉浸式引入 — 🐾 「喵星终端」启动

**目标**：用趣味交互替代冷冰冰的授权按钮，第一秒就建立"全员变猫"的世界观认知。

| 元素 | 设计 |
|------|------|
| 视觉 | 赛博萌系「喵星扫描仪」全屏动画——荧光线条勾勒的猫脸轮廓 + 扫描网格 |
| 交互 | 用户**长按屏幕**（模拟猫爪按压），触发按压涟漪效果 |
| 音效 | 猫咪呼噜声 → "喵呜" 确认音 |
| 文案 | "正在读取你的峡谷基因……" → "检测到一只隐藏的猫！" |
| 授权 | 长按触发游戏账号授权弹窗（微信/QQ 登录，拉取游戏数据权限） |
| 时长 | ~5 秒（含长按 2s + 动画 3s） |

**设计要点**：
- 长按反馈：按压区域出现发光猫爪印，压力越大爪印越亮
- 授权失败态：扫描仪显示"信号干扰……喵星终端重试中"，引导重新授权
- 未登录态：仍可进入阶段二答题，但阶段三/四使用默认数据 + 提示"授权后解锁完整猫格"

---

### 阶段二：「喵格人格问卷」— 3~5 题快速测试

**目标**：用轻松有趣的选择题获取玩家性格标签，同时后台并行拉取游戏数据。

**题目设计原则**：
1. 每题 2-4 个选项，选项本身就是段子/梗
2. 题目覆盖：游戏风格 + 社交倾向 + 心态特征
3. 每个选项对应一组隐藏标签（影响最终猫种匹配）

**示例题目**：

| # | 题目 | 选项 | 隐藏标签 |
|---|------|------|---------|
| Q1 | 开局30秒，你会？ | A. 直奔对面野区蹲草丛 / B. 默默补兵等发育 / C. 疯狂ping队友"跟我来" / D. 切出去回消息 | 侵略型 / 稳健型 / 指挥型 / 佛系型 |
| Q2 | 队友送了3个人头，你的反应？ | A. "没事兄弟稳住" / B. 默默叹气继续打 / C. 开始指挥全队运营 / D. 直接开喷 | 包容型 / 隐忍型 / 领袖型 / 暴躁型 |
| Q3 | 选一只最像你的猫 | A. 🧶 追逐激光笔的橘猫 / B. 🛋️ 沙发上躺平的英短 / C. 🏔️ 独自巡视领地的豹猫 / D. 🐾 蹭人求摸的布偶 | 好动型 / 懒散型 / 独行型 / 粘人型 |
| Q4 | 你的峡谷座右铭？ | A. "稳住我们能赢" / B. "冲就完了" / C. "我carry你们躺" / D. "开心就好" | 团队型 / 莽夫型 / 自信型 / 佛系型 |

**交互设计**：
- 每题一屏，选项卡片式布局，点击带猫爪拍击动效
- 选完自动过渡到下一题（无需确认按钮）
- 进度条为猫尾巴造型，随答题进度伸展

---

### 阶段三：AI 猫管家加载 — 等待页包装

**目标**：把 2-3 秒的数据加载等待变成沉浸式小彩蛋，同时拉取并处理玩家历史对局数据。

| 元素 | 设计 |
|------|------|
| 动画主体 | 一只穿着白大褂的 AI 小猫在疯狂敲键盘（逐帧/Lottie 动画） |
| 弹幕效果 | 屏幕飞速闪过玩家近期的游戏词条标签（实时数据） |
| 词条示例 | "五杀！" / "超神" / "连跪7把" / "0/8/2的那个夜晚" / "MVP收割机" / "补刀王" / "视野大师" |
| 底部文案 | 滚动播放："正在分析你的 1,247 场对局……" → "发现了一些不忍直视的数据……" → "正在给你匹配猫种……" |
| 音效 | 键盘敲击声 + 偶尔的猫叫 |

**后台并行处理**：

```
前端展示加载动画
     ↓
     ├── API 请求1: 拉取玩家基础数据（KDA/胜率/常用位置/常用英雄）
     ├── API 请求2: 拉取近期对局高光/下饭标签
     └── API 请求3: 结合问卷标签 + 游戏数据 → AI 猫格生成
              ├── 匹配猫种
              ├── AI 生成个性化文案
              └── AI 生成专属猫咪形象
```

**异常处理**：
- 数据拉取超时（>5s）：加载动画延长 + 文案变为"你的数据有点多，猫管家正在加班……"
- 数据拉取失败：使用问卷标签 + 默认数据生成基础版猫格 + 提示"授权后解锁完整版"

#### 4.2 AI 千人千猫视觉生成

**核心差异化**：每个玩家生成的猫在视觉上独一无二。

**设计原则：元素提取，而非英雄还原**

> 猫咪本体保持自然猫的形态和萌感，只从玩家常用英雄身上**提取标志性的色彩、纹样、小配饰**融入猫的外观。
> 目标是让了解英雄的人能会心一笑「哦这是 XX 元素」，而不是让猫变成英雄的 cosplay 版。

**🔧 前置工作：英雄元素拆解 → 猫特质映射**

在做视觉生成之前，需要先对每个英雄完成标准化的**元素拆解**，再将拆解出的元素映射到猫的对应部位。这是设计师/美术的前置产出物，也是图层制作的依据。

**拆解流程**：`英雄原画分析 → 提取核心视觉元素 → 映射到猫的身体部位 → 输出设计规范`

**猫特质映射标准（7 个映射位）**：

| 猫的部位 | 映射来源 | 映射规则 | 示例（亚索） | 示例（安妮） | 示例（锤石） |
|---------|---------|---------|------------|------------|------------|
| 👁️ **瞳色** | 英雄技能元素色 / 分路色 | 从英雄技能特效中提取最具辨识度的 1 个颜色作为瞳色；若英雄元素色不突出则 fallback 到分路色 | 风元素蓝（偏钴蓝） | 火焰橙红 | 幽魂绿 |
| 🎨 **毛色/毛尖渐变** | 英雄主题色（色相+明度） | 提取英雄原画/技能中的 1 个主色调，作为猫的整体毛色基调或毛尖渐变色 | 蓝灰色渐变毛尖 | 暖橘红毛色 | 深灰底 + 微绿光泽 |
| 🐾 **爪垫/鼻头纹样** | 英雄标志性图案（微缩化） | 从英雄最具辨识度的视觉符号中提取一个，缩小为爪垫或鼻头上的小印记 | 风旋涡纹 | 小火焰纹 | 锁链环纹 |
| 👂 **耳朵特征** | 英雄头部/发型标志 | 把英雄头部最显著的特征抽象为猫耳的形态/装饰 | 耳尖有风纹发丝飘带 | 耳朵内侧火焰色绒毛 | 耳朵边缘幽光描边 |
| 🐈 **尾巴特征** | 英雄技能视觉/武器形态 | 从英雄技能特效或武器造型中抽象为尾巴的末端形态/光效 | 尾尖有风刃形分叉 | 尾巴末端微微发光（余烬效果） | 尾巴缠绕一圈暗绿锁链纹 |
| 🎀 **项圈/挂坠** | 英雄标志性物件（Q版迷你化） | 英雄最具辨识度的武器/道具，做成迷你 Q 版挂坠系在猫脖子上 | 微缩风刃坠子 | 迷你提伯斯小熊坠子 | 小灯笼坠子 |
| ✨ **额头/身体印记** | 英雄被动/大招视觉符号 | 英雄被动技能或大招中最有标志性的视觉符号，作为猫额头或身体上的隐约印记 | 额头浮现「斩」字风纹（若满层时微微发光） | 背部隐约的火焰翼纹 | 胸口暗绿灵魂漩涡印记 |

#### 4.4 AI 文案生成逻辑

AI 生成的文案分三层：

| 层级 | 内容 | 数据依赖 | 生成方式 |
|------|------|---------|---------|
| **猫格诊断** | 2-3 段个性化分析 | KDA + 常用英雄 + 常用位置 + 胜率 + 问卷标签 | LLM 生成（Prompt 模板 + 数据注入） |
| **猫管家点评** | 1 句毒舌/暖心总结 | 猫种 + 数据亮点/槽点 | LLM 生成 |
| **冷知识彩蛋** | 1-2 条数据趣味化 | 总死亡/总场次/草丛时长/技能释放次数等 | 公式计算 + 模板填充 |

**Prompt 设计要点**：
- 语气：毒舌但不冒犯，损人但不攻击，像朋友之间的吐槽
- 禁区：不嘲讽段位低、不暗示充钱、不涉及负面情绪攻击
- 必须：每段文案至少包含 1 个来自玩家真实数据的具体细节（如英雄名/具体数字）

### 6.2 关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 猫咪生成 | 图层合成（预制模型 + 可变图层） | 成本低、延迟 <1s、组合足够丰富 |
| 文案生成 | LLM（混元/DeepSeek）+ Prompt 模板 | 个性化强、数据驱动 |
| 分享图 | 服务端 Canvas 渲染 → 静态图 | 兼容微信/QQ 分享（需要图片链接） |
| 前端框架 | Vue3 + Vant | 移动端 H5 标准选型，团队熟悉 |
| 数据缓存 | Redis（猫格结果缓存 24h） | 避免重复 LLM 调用 |
| PK 匹配 | 基于猫格 ID 的键值对匹配 | 无需实时对战，简化实现 |

### 6.3 数据接口依赖

| 接口 | 数据 | 来源 | 用途 |
|------|------|------|------|
| 玩家基础数据 | UID/昵称/段位/头像 | LOLM 开放平台 | 身份展示 |
| 对局汇总数据 | KDA/胜率/场次/常用英雄/常用位置 | LOLM 数据平台 | 猫种匹配 |
| 对局明细数据 | 近 50 场对局详情 | LOLM 数据平台 | 冷知识 + 高光词条 |
| 社交关系链 | 好友列表 | LOLM 社交接口 | PK 邀请（可选） |

### 6.4 三态设计

| 场景 | 正常态 | 空态 | 错误态 |
|------|--------|------|--------|
| 授权 | 正常拉取数据 | 未登录：可体验但展示默认猫 + 引导授权 | 授权失败：重试 + 降级方案 |
| 数据加载 | 2-3s 完成 | 新号（无数据）：纯问卷驱动生成 | 超时/接口异常：兜底模板 |
| AI 文案 | LLM 实时生成 | — | LLM 异常：使用预设模板文案 |
| PK 匹配 | 同屏展示 + AI PK 报告 | 好友未完成：展示邀请等待页 | 数据异常：通用 PK 模板 |

### 9.2 关键埋点

### B. AI Prompt 设计框架（核心逻辑参考）

```
你是「峡谷猫格诊断师」，一只毒舌但有爱的AI猫管家。

玩家数据：
- 猫种：{cat_type}
- KDA：{kda}
- 胜率：{win_rate}
- 常用英雄：{top_heroes}
- 常用位置：{main_role}
- 总场次：{total_games}
- 近期状态：{recent_trend}

任务：生成一段 100-150 字的猫格诊断书。

规则：
1. 语气：像好朋友之间的吐槽，损人但不冒犯
2. 必须包含至少 2 个来自玩家真实数据的具体细节
3. 必须点出一个优点 + 一个可吐槽的弱点
4. 结尾给一句话建议（可以是反话/正话/哲学式）
5. 禁止：嘲讽段位、暗示充钱、人身攻击、负面情绪攻击
```

### C. PK Prompt 设计框架

```
你是「峡谷猫格裁判猫」。现在有两只猫进行 PK：

猫 A：{cat_a_type}，数据：{cat_a_data}
猫 B：{cat_b_type}，数据：{cat_b_data}
关系类型：{relation_type}

任务：生成 100-200 字的 PK 判定报告。

规则：
1. 先给一个契合度数字（1-100%）
2. 根据关系类型调整语气：
   - 天作之合：甜蜜互夸但带刺
   - 一山不容二猫：挑拨约架但好笑
   - 血脉压制：替弱的那个说话但很搞笑
3. 必须引用双方的真实数据对比
4. 结尾给一个建议（组双排/开自定义单挑/让弱的选悠米等）
5. 禁止：人身攻击、性别歧视、段位歧视
```
