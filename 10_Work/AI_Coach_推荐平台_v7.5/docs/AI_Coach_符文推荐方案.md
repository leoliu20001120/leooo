## 一、产品场景回顾

海克斯大乱斗共有 **4个阶段** 选符文（S1开局/S2七级/S3十一级/S4十五级），每次有 **3个同等级** 的随机符文挑选（等级为白银/黄金/棱彩，由游戏随机决定，并非固定S1=白银），每个符文有 **1次刷新机会**。

AI Coach 需要：
1. **三分类Logo**：👍点赞 / 🤔思考 / 🔄建议刷新
2. **评价推荐话术**：综合符文属性、英雄适配、黑科技组合、UGC评论
3. **动态评分**：根据阶段、已选符文、连胜/连败状态动态调整

## 二、评分函数设计

### 2.1 核心公式

```
最终得分 = (基础分 + 英雄纠偏分) + 黑科技组合加成(含阶段系数)
```

> 💡 **v7.5 关键修正**：
> - **去掉连胜连败额外乘数**（原有×0.96/×0.92/×1.04/×1.08），连胜/连败差异完全通过基础分中的权重profile体现
> - **英雄胜率纠偏**：低胜率英雄提分，高胜率英雄降分，使推荐更公平
> - 阶段系数不再是独立的乘法因子，而是和黑科技组合加成绑在一起的
> - **通用黑科技组合**：只有S1/S2阶段才给黑科技加成（因为还有机会凑第二张），S3/S4不给（除非已选过组合件）
> - **英雄专属黑科技**：不受阶段限制，S1-S4都给加成（因为单卡即生效，不需要凑组合）

### 2.2 基础分计算（0-100分）

```python
基础分 = (
    符文胜率分 × W_winrate      # 数据源：hextech_augments.json win_rate（该英雄选这个符文的全局胜率）
  + 符文选择率分 × W_pickrate   # 数据源：hextech_augments.json pick_rate（全局选择率）
  + UGC评分分 × W_ugc          # 数据源：zhangmeng_ugc.json score (10分制)
)
```

> 💡 **简化说明**：基础分只保留3个维度。"符文胜率"就是该英雄选这个符文的胜率，胜率本身已隐含了英雄适配信息，越简单越好，方便后续调参。

**各维度归一化方法：**

| 维度 | 数据源 | 归一化公式 | 说明 |
|------|--------|-----------|------|
| 符文胜率分 | `hextech_augments.win_rate`（全局） | `(wr - 45) / 25 × 100` | 45%→0分, 70%→100分 |
| 符文选择率分 | `hextech_augments.pick_rate`（全局） | `min(pr / 3.0, 1.0) × 100` | 选取率反映社区共识 |
| UGC评分分 | `zhangmeng_ugc.score` (10分制) | `score / 10 × 100` | 无评分则默认50 |

> 💡 **归一化公式设计依据**（基于实际数据范围）：
> - **胜率** `(wr-45)/25×100`：全局胜率范围约43.93%~67.39%，用45%作为下界（低于45%≈随机水平→0分）、70%作为上界（→100分），覆盖绝大多数数据且留有余量
> - **选择率** `min(pr/3.0,1.0)×100`：全局选择率范围约0%~2.08%，用3%作为饱和点，超过3%不再加分。大部分符文选择率在0~2%之间，3%已是极高热门
> - MVP版本使用**全局胜率/选择率**，暂不按阶段拆分（阶段样本量差异大，特别是第5阶段数据极少导致偏差）

**默认权重（连胜/连败通过切换权重profile实现差异）：**

| 场景 | W_winrate | W_pickrate | W_ugc | 说明 |
|------|-----------|------------|-------|------|
| **标准模式** | 0.60 | 0.15 | 0.25 | 平衡模式 |
| **连胜模式（≥3连胜）** | 0.40 | 0.15 | 0.45 | 偏向娱乐/UGC |
| **连败模式（≥3连败）** | 0.75 | 0.15 | 0.10 | 偏向实力/胜率 |

> 💡 **设计理念**：
> - 连胜时降低胜率权重、提高UGC权重，鼓励用户追求有趣体验（黑科技/娱乐流）
> - 连败时大幅提高胜率权重，帮用户稳住局面
> - 权重加起来=1.0，简单易调
> - **v7.5变更**：不再额外乘连胜/连败系数（原0.96/0.92/1.04/1.08），所有差异完全通过上述权重配置体现。三组权重均可在前端参数面板实时调整

### 2.3 黑科技组合加成 + 标签判定（v2.2 — 阶段系数绑定黑科技）

黑科技标签判定需要考虑**3个维度**：通用黑科技组合是否适配当前英雄、阶段、英雄专属黑科技。

> 💡 **v2.8核心修正**：黑科技加成降低，阈值按等级分层。专属黑科技+20，组合成型+20，潜在组合+5，上限20。

```python
def 判定黑科技标签和加成(当前符文, 已选符文列表, 当前阶段, 当前英雄):
    """
    返回: (加成分, 标签, 话术)
    
    ★ v2.8: 黑科技加成调低，上限20
    - 英雄专属黑科技：不考虑阶段，+20
    - 通用组合成型+适配英雄：+20
    - 通用组合S1/S2潜在（适配但未成型）：+5
    - 通用组合S3/S4适配但未成型：+5
    - 通用组合成型但不适配英雄：+3
    """
    加成 = 0
    标签 = None
    话术 = ""
    
    # ========== 一、英雄专属黑科技（不受阶段限制，+20） ==========
    # ★ v2.8: 专属黑科技+20（原+30）
    # ★ v2.5修正：英雄专属黑科技表中用的是称号(如"复仇焰魂")，需双向映射(称号/中文名都能匹配)
    if (当前英雄, 当前符文) in 英雄专属黑科技库:
        专属 = 英雄专属黑科技库[(当前英雄, 当前符文)]
        加成 = 20   # v2.7: 专属黑科技+20
        标签 = "黑科技"
        是英雄专属 = True  # 标记已触发英雄专属，后续通用组合跳过
        话术 = 专属.话术
    
    # ========== 二、通用黑科技组合（阶段系数在这里体现） ==========
    for 组合 in 通用黑科技组合库:   # 25个2符文核心组合
        if 当前符文 not in [组合.aug1, 组合.aug2]:
            continue
        
        适配 = 组合适配英雄(组合, 当前英雄)
        另一半 = 组合.aug2 if 当前符文 == 组合.aug1 else 组合.aug1
        已有另一半 = 另一半 in 已选符文列表
        
        if 已有另一半 and 适配:
            # 组合成型 + 适配英雄！任何阶段+20
            加成 += 20
            标签 = "黑科技"
            话术 = f"组合成型！{组合.pitch}"
        
        elif 已有另一半 and not 适配:
            # 组合成型但不适配英雄 → +3（组合效果还在但英雄用不好）
            加成 += 3
        
        elif 当前阶段 <= 2 and 适配:
            # ★ S1/S2 + 适配英雄 → +5，显示黑科技标签
            加成 += 5
            if 标签 != "黑科技":
                标签 = "黑科技"
                话术 = 组合.pitch
        
        elif 当前阶段 > 2 and 适配:
            # S3/S4 + 适配但没有另一半 → +5，不显示黑科技标签
            加成 += 5
        
        # ★ 不适配英雄 + 未成型 → 直接跳过，不加分
    
    # ========== 三、套装羁绊加成（独立于黑科技标签） ==========
    for 套装 in 官方9个套装:
        套装内已有 = len(set(已选符文列表 + [当前符文]) & set(套装.augments))
        if 套装内已有 >= 2:
            加成 += 5 * 套装内已有
    
    return min(加成, 20), 标签, 话术


def 组合适配英雄(组合, 英雄):
    """判断黑科技组合是否适配当前英雄"""
    # 方式1：英雄在组合的推荐英雄列表中
    if 英雄 in 组合.example_heroes:
        return True
    # 方式2：英雄类型匹配（如坦克英雄 + 体型流组合）
    英雄类型 = 获取英雄类型(英雄)  # 从champion_combos数据推断
    if 英雄类型 in 组合.hero_type:
        return True
    return False
```

**关键设计决策：**

| 场景 | 标签 | 加成 | 理由 |
|------|------|------|------|
| 火男S1+祖母辣椒油 | **黑科技** | +5 | 灼烧流适配火男 + S1阶段潜在组合 |
| 火男S1+歌利亚巨人 | 不触发 | +0 | 体型流不适配火男 → **不适配的组合直接跳过** |
| 火男S3+炼狱导管（未选过辣椒油） | **黑科技** | +20 | 炼狱导管是火男**英雄专属黑科技**（单卡即生效） |
| 火男S3+炼狱导管（已选辣椒油） | **黑科技** | +20 | 英雄专属黑科技+20（封顶20） |
| 蒙多S1+坦克引擎 | **黑科技** | +5 | 体型流适配蒙多 + S1阶段潜在组合 |
| 蒙多S3+歌利亚巨人（未选过组合件） | 强牌 | +5 | S3适配但未凑齐 → 适配未成型+5 |
| 蒙多S3+歌利亚巨人（S1已选坦克引擎） | **黑科技** | +20 | 已有组合件 → 组合成型！ |
| 奥拉夫S1+缩小引擎 | 不触发 | +0 | AP流不适配物理战士 → **直接跳过** |
| 3张都弱 | 3张都**刷新** | - | 不强制推荐，3张都可建议刷新 |

#### 例1：丽桑卓S1 + 缩小引擎（S1适配英雄，未成型 → 黑科技 +15分）

```

当前符文: 缩小引擎

```

**判定过程：**
1. **英雄专属黑科技**：丽桑卓+缩小引擎 → 不在专属库中 → 跳过
2. **通用黑科技组合**：遍历25个组合，找到3个包含「缩小引擎」且适配丽桑卓的组合：
   - 缩小引擎+超凡邪恶（AP风筝流）→ S1阶段 + 丽桑卓在适配英雄列表 → **+5分**
   - 扇巴掌+缩小引擎（控制叠层流）→ S1阶段 + 丽桑卓适配 → **+5分**
   - 吞噬灵魂+缩小引擎（坦控叠层流）→ S1阶段 + 丽桑卓适配 → **+5分**
   - ❌ 祖母的辣椒油+缩小引擎（灼烧缩小流）→ 丽桑卓**不在**适配英雄列表 → **直接跳过，+0分**
3. **套装羁绊**：缩小引擎单卡不触发任何套装 → +0分

```
┌─ 结果 ─────────────────────────────
│ 加成分: +15 (5+5+5)
│ 标签:   黑科技
│ 话术:   小身板高法强
└──────────────────────────────────────
```

> ✅ **为什么标"黑科技"？** S1阶段有3个适配组合可以去凑，后面3次选牌机会很充足。话术来自第一个匹配到的组合"AP风筝流"的推荐话术。

2. **通用黑科技组合**：无限循环往复参与2个组合（AP急速流、控制急速流），但布兰德不在适配英雄列表 → **全部跳过，+0**
3. **套装**：无限循环往复+物法皆修 都属于「叠角龙」套装 → 2件 × 3 = **+6分**

```

│ 标签:   强牌
│ 话术:   无限CD
```

- 🔑 **总加成封顶20分**，防止多组合叠加导致分数爆炸

### 2.4 三分类Logo阈值（v7.3+ — 分英雄自适应阈值）

> 💡 **v7.3核心升级**：阈值不再是全局固定值，而是**按英雄×等级自适应调整**，确保每个英雄每个等级都有 TARGET（默认4个）左右的推荐符文，范围为 [MIN, MAX]（默认2~6个）。

```python
# 自适应阈值计算逻辑
def get_threshold(champion_id, stage, augment_level):
    """
    为每个英雄×等级动态计算推荐阈值和考虑阈值
    
    目标：保证每英雄每等级约 TARGET_RECOMMEND_PER_LEVEL 个推荐 (默认4)
    范围：[MIN_RECOMMEND_PER_LEVEL, MAX_RECOMMEND_PER_LEVEL] (默认2~6)
    
    方法：对该英雄所有该等级符文的得分排序，
         通过二分查找找到一个阈值使推荐数量接近TARGET
    """
    # 收集该英雄×该等级所有符文的得分
    scores = [calc_score(aug, champion_id) for aug in augments_of_level]
    scores.sort(reverse=True)
    
    # 推荐阈值 = 第 TARGET 个得分（确保约 TARGET 个推荐）
    recommend_threshold = scores[TARGET - 1] if len(scores) >= TARGET else scores[-1]
    # 考虑阈值 = 推荐阈值 - 间距
    consider_threshold = recommend_threshold - gap
    
    return recommend_threshold, consider_threshold
```

**可调参数（前端面板可实时调整）：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| TARGET_RECOMMEND_PER_LEVEL | 4 | 每英雄每等级目标推荐数量 |
| MIN_RECOMMEND_PER_LEVEL | 2 | 最少推荐数 |
| MAX_RECOMMEND_PER_LEVEL | 6 | 最多推荐数 |
| REFRESH_BOTTOM_PERCENT | 20% | 建议刷新：排名最后20% |

> ⚠️ **为什么需要自适应？** 不同英雄的符文得分分布差异很大——高胜率英雄的符文普遍高分，低胜率英雄的符文普遍低分。固定阈值会导致某些英雄全是推荐、某些英雄全是刷新。自适应阈值确保每个英雄都有合理的推荐分布。

**Logo判定规则：**

```python
def 判定Logo(最终得分, champion_id, augment_level):
    推荐阈值, 考虑阈值 = get_threshold(champion_id, stage, augment_level)
    if 最终得分 >= 推荐阈值:
        return "👍 推荐选取"     # 绿色点赞Logo
    elif 最终得分 >= 考虑阈值:
        return "🤔 值得考虑"     # 黄色思考Logo
    else:
        return "🔄 建议刷新"     # 灰色刷新Logo
```

**核心原则：**
- ⚠️ **每张符文独立评分**：同一阶段出现的3张符文可能3张都推荐（都≥推荐阈值），也可能3张都建议刷新（都<考虑阈值），不做强制分布
- ⚠️ **分数本身不变**：自适应的是阈值而非分数，同一张符文在S1和S3的评分差异仍然由黑科技加成决定

### 2.5 英雄胜率纠偏（v7.3+）

> 💡 不同英雄整体胜率差异很大（如全英雄平均约49.55%），直接按符文胜率打分会导致低胜率英雄几乎没有推荐、高胜率英雄推荐过多。通过英雄纠偏使推荐数量更公平。

```python
英雄纠偏分 = (全英雄平均胜率 - 该英雄平均胜率) × 纠偏强度 × 100 / (WR_CEILING - WR_FLOOR)
# 结果 clamp 到 [HERO_CORRECTION_MIN, HERO_CORRECTION_MAX]
```

**可调参数（前端面板可实时调整）：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| HERO_CORRECTION_STRENGTH | 0.3 | 纠偏强度（0~1） |
| HERO_CORRECTION_MAX | +8.0 | 纠偏上限（弱英雄最多加8分） |
| HERO_CORRECTION_MIN | -5.0 | 纠偏下限（强英雄最多扣5分） |

### 2.6 连胜娱乐逻辑（v7.5 — 分数调整法）

> 💡 连胜≥3时触发"娱乐逻辑"，目的是让连胜用户体验更多有趣符文组合，避免总是推相同的"最优解"。

**核心机制：**
1. **降级**：将"最佳拍档"和"强力单卡"标签卡片**合并**后按分数排序，后 `WINNING_DEMOTE_PERCENT`%（默认50%）施加负分数惩罚，使其跌落到"值得考虑"区域
2. **提升**：娱乐标签符文加 `ENTERTAINMENT_BOOST`（默认15分），使其提升到"推荐选取"区域
3. **重新排序**：调整分数后重新排序并重新判定logo

**小样本保护机制（v7.5新增）：**
- 当"最佳拍档+强力单卡"合并后候选≤2个时，**不执行降级**
- 原因：候选太少说明该英雄的黑科技/强力卡本来就很少，强制降级会把最好的符文误降级
- 案例：布兰德棱彩只有2个最佳拍档（巨人杀手+炼狱导管），合并后仍≤2个，不降级 → 炼狱导管连胜时保持"推荐选取" ✅

**可调参数：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| WINNING_DEMOTE_PERCENT | 50% | 降级比例（合并排序后取后X%） |
| ENTERTAINMENT_BOOST | 15分 | 娱乐符文加分 |

> ⚠️ **v7.5变更说明**：
> - 原来"最佳拍档"和"强力单卡"**各自独立**排序取后50%，导致小样本下（如只有2个最佳拍档）top符文也被降级
> - 现改为**合并排序**：最佳拍档+强力单卡合并为一个列表统一排序后取后50%，并增加候选≤2个的保护机制

评分完成后，根据分数和英雄黑科技数据，为每个符文打上标签：

| 标签 | 判定规则 | 说明 |

## 四、推荐话术生成方案

### 4.1 话术核心原则

- **不出现具体胜率/选取率数字**
- **用定性描述**：如"表现极为出色"、"社区公认强力"

### 4.2 话术格式

**黑科技组合话术：**
```
黑科技 | {≤10字话术}
```
示例：`黑科技 | 双灼烧叠加`、`黑科技 | 叠血变大`、`黑科技 | 控住就炸`

**强牌话术：**
```
强牌 | {≤10字理由}
```
示例：`强牌 | 法师通用神器`、`强牌 | 坦度拉满`

**趣味话术：**
```
趣味 | {≤10字玩法}
```
示例：`趣味 | 无限雪球`、`趣味 | 超远击飞`

### 4.3 黑科技组合提示（当凑齐时）

当用户已选过黑科技组合的其中1个符文，后续阶段又出现另一个时：
```
黑科技成型！ | {话术}
已有{符文A}+{符文B}={流派名}
```
示例：`黑科技成型！ | 双灼烧叠加 已有辣椒油+炼狱导管=灼烧流`
