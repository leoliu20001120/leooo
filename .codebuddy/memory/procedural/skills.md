## 已验证工作流

### 📖 读书笔记 → 课程化
**触发**: 用户说"课程化"或"同样处理"

1. 读取现有笔记 → 了解已有内容和结构
2. Web搜索原书目录 + 中文读书笔记（知乎/GameRes等）
3. 按原书章节拆分，每章一个 md 文件
4. 创建TODO → 按批次（4-5章一组）
5. 批量创建: `_README.md` + 各章 + `附录_速查表.md`
6. 每章格式: 核心内容 → 案例 → 练习 → 金句 → 延伸阅读 → 章节导航 → 跨书关联
7. 写入 episodic 日志

**已应用**: 《游戏设计艺术》36文件、《快乐之道》16文件

### 📊 知识库扩充
**触发**: 用户要求扩充/补充知识库

1. 读取现有知识库 → 了解范围和格式
2. Web搜索+爬取 → 多来源获取新数据
3. **交叉校验** → 与现有数据比对，标注冲突/新增
4. 结构化整理 → Excel多Sheet分类
5. **独立文件存储** → 绝不覆盖已有文件
6. 输出校验报告

### 🎨 产品原型迭代

1. **第一性原理Review** → 从用户任务出发审视
2. 问题分类 → 按严重度排序（🔴🟡🟠）
3. 设计改进 → 不追求视觉炫技
4. 实现 + 更新说明文档 + 版本号递增

### 🌐 H5 Demo 快速原型
**触发**: 用户要求做 H5 Demo / 营销页 / 交互原型

1. PRD + Mock 数据契约 → 定义接口和数据结构
2. 单文件 HTML（CSS+JS 内联）→ 快速出 MVP
3. Mock 数据逻辑 → 纯前端模拟（哈希/随机/状态机）
4. 视觉升级 → 逐步 replace_in_file（避免 token 溢出），不要一次性重写
5. 内容升级 → 替换文案/题目/对话，保持结构不变
6. 功能迭代 → 新增组件（Bottom Sheet / 粒子系统等）

**已应用**: 异人体检站 H5 Demo（5轮迭代）

### 🤖 AI 团队多角色评审
**触发**: 用户要求做评审 / 技术方案评估 / 综合评估

1. 组建多角色团队（常用: PM / Tech-Lead / QA-Lead / Project-Manager）
2. 各角色独立产出评审文档
3. 跨团队意见交叉验证 → 达成共识
4. main 角色汇总 → 综合评审报告
5. 后续交付物：开发启动包（Kickoff材料 / TAPD任务 / Week1清单 / 埋点）

**已应用**: 异人体检站 PRD 评审（4角色，产出9份文档）

### 🎮 UC 对局复盘测试闭环
**触发**: 用户说"ucgit pull/push/commit"或涉及 analysis.go 修改

1. `git pull` 拉最新代码
2. 修改 `analysis.go`
3. `git add + commit + push`（master 分支 → git.woa.com）
4. 运行 `upload_and_report.py` 批量测试 46 个 JSON
5. 分析 `result.xlsx` → 对比变化 → 数据可视化

## 思维与输出原则

### 🧱 第一性原理
- 每个决策/分析前，**回到最基本的事实和约束**，追问"为什么"直到触底
- 不接受"因为大家都这么做"作为理由，从底层逻辑推导

### 🔍 批判性思维
- 对假设保持怀疑：我的前提成立吗？有没有反例？
- 区分**事实 vs 观点 vs 推测**，明确标注不确定性
- 主动寻找反面论据，不做选择性呈现

### 🔺 金字塔原理（输出结构）
- **结论先行**：开头直给答案/核心观点
- **分组归类**：同类信息归到一起，MECE（互斥穷尽）
- **逻辑递进**：每组内部按逻辑顺序排列（时间/重要性/因果）
- 所有文档输出必须结构化，拒绝"意识流"式铺陈
