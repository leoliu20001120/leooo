# 🤖 AI 团队多角色评审法

> 从「异人体检站」PRD 全面评审中提炼。适用于产品方案评审、技术方案评估、立项评估等需要多视角分析的场景。

---

## 核心理念

**多角色独立评审 → 交叉验证 → 共识收敛 → 行动交付物**

单一视角的评审容易有盲区。让 AI 扮演不同专业角色，各自独立产出，再交叉碰撞，产出质量远超单角色。

---

## 五步流程

### Step 1：组建角色团队
根据评审对象选择角色组合：

| 评审类型 | 推荐角色 |
|----------|----------|
| PRD 评审 | PM + Tech-Lead + QA-Lead + Project-Manager |
| 技术方案评审 | Tech-Lead + Architect + QA-Lead |
| 立项评估 | PM + Business Analyst + Project-Manager |
| 运营活动评审 | PM + Marketing + Data Analyst |

**关键**：每个角色必须有明确的关注点和产出模板。

### Step 2：各角色独立产出
- 每个角色**独立**阅读材料、产出评审文档
- 不要让角色互相看对方的产出（避免锚定效应）
- 每份评审文档包含：评审结论 + 发现的问题 + 建议 + 风险

### Step 3：跨团队交叉验证
- 将各角色的产出交叉发送（PM 看 Tech 的、Tech 看 QA 的…）
- 收集反馈意见，标注：✅同意 / ⚠️补充 / ❌不同意
- **重点关注**：各角色对同一问题的不同看法

### Step 4：共识汇总
- Main 角色汇总所有评审意见
- 产出综合评审报告：
  - 整体评分（A/B/C/D）
  - 跨团队共识项（PM×Tech / Tech×QA / PM×QA）
  - 分歧项及最终决策
  - 风险矩阵（概率 × 影响）
  - 排期修正建议

### Step 5：行动交付物
评审通过后，产出"开发启动包"：

1. **Kick-off 材料** — 一页纸项目概览 + 会议议程
2. **任务拆解** — WBS → 可执行任务（含负责人/工时/依赖/验收标准）
3. **Week 1 执行清单** — Day-by-Day 行动计划
4. **数据埋点清单** — 事件定义 + 看板指标
5. **启动包汇总** — 文档索引 + 准入 Checklist

---

## 关键原则

| 原则 | 说明 |
|------|------|
| 🔀 独立先行 | 各角色独立评审，避免群体思维 |
| 🔄 交叉碰撞 | 不同角色互看产出，发现盲区 |
| 📊 量化结论 | 评分有标准（A-D），排期有数字（工期/人天/人数） |
| 📦 交付导向 | 评审不是终点，启动包才是 |
| ⚖️ 排期校正 | 经验公式：初始排期 × 1.5 ≈ 实际工期 |

---

## 实战数据

异人体检站评审结果（4 角色，9 份文档）：
- 评分：B+ → A-（迭代后上调）
- 排期校正：5-6 周 → 8-9 周（+50%）
- 人天校正：45 → 80-95（+80%）
- 团队校正：10-11 → 15-17 人（+50%）
- 测试校正：7 天 → 15-18 天（+150%）
