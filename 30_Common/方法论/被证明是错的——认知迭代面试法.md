# "被证明是错的" —— 认知迭代面试法

> 来源：Boris Cherny（Anthropic Claude Code 创始人）的经典面试题
> 原文："你有没有'被证明是错的'例子？"

---

## 一、这道题在考什么？

| 层次 | 考察点 | ❌ 差的信号 | ✅ 好的信号 |
|------|--------|------------|------------|
| **表层** | 自我觉察 | "我想不到" / "我一般都挺对的" | 能快速举出具体例子 |
| **中层** | 处理"被打脸"的方式 | "后来证明我也没全错" | 承认错了 + 讲清楚怎么更新的 |
| **深层** | 认知迭代速度 | 事后很久才勉强承认 | 当时就能接受新证据并调整 |

### 底层逻辑

Boris 问这个问题，本质是在考：**你跟自己观点之间的关系**。

- 🟢 **好信号**：我会形成强观点，但松散持有（hold loosely）—— 新证据来了就更新
- 🔴 **坏信号**：我没什么强观点 / 我的强观点从来没错过

> 这是 Anthropic 文化的缩影：他们的 CLAUDE.md 哲学就是"发现模型犯错 → 写规则 → 每代模型更新后删规则重来"。整个公司就是一个持续证伪的机器。

## 二、回答结构：STAR + 反转

```
1. Situation — 我之前坚定地相信 X
2. 为什么信 — 我的依据/推理是什么（证明你不是随便下判断）
3. 反转   — 什么新证据/经历证明我错了
4. Update  — 我怎么更新了自己的认知
5. Meta    — (加分) 这件事教会了我关于"如何形成观点"的什么
```

### 满分模板

> **"有的。在 [时间/项目] 时，我非常坚信 [X 观点]。我的依据是 [Y 理由]——这在当时看来是合理的。**
>
> **但后来 [Z 事件/数据/反馈] 出现了，直接推翻了我的假设。具体来说，[简要说明矛盾]。**
>
> **我最终更新了认知：[新观点]。这件事教会了我一个更底层的道理——[meta-lesson]。"**

## 三、素材方向（AI PM 视角）

### 方向 A：对技术能力的错误判断

> "我之前认为 XX 技术做不到 / 不够好，结果……"

**示例**：做 NPC 时认为 LLM 不可能在保持角色一致性的同时处理复杂叙事分支（依据是早期模型测试），后来通过分场景知识库 + 精细 prompt 策略远超预期。

**Meta-lesson**：不要用今天的模型能力锁死产品设计的天花板。

### 方向 B：对用户需求的错误假设

> "我以为用户要 A，结果他们要 B"

**示例**：做对局复盘时假设玩家最想看详细数据分析报告，但 93.5% 的反馈里无具体数字——用户要的是决策级建议（"这波应该先打谁"），不是统计报告。

**Meta-lesson**：要区分"精准"和"可操作"，用户要的是后者。

### 方向 C：对工作方法的信仰被推翻

> "我一直相信 XX 方法论，直到……"

**示例**：曾坚信 PM 必须先写详尽 PRD 才能推进开发。在快速原型迭代中发现直接做 demo 对齐效率高 3 倍。与 Boris 的"Show, don't write"完全一致。

**Meta-lesson**：当构建成本降低后，文档沟通反而成了摩擦。

### 方向 D：对人/团队的错误判断

> "我以为他不行 / 这个方案不靠谱，结果……"

## 四、回答大忌

| 大忌 | 为什么致命 |
|------|-----------|
| "我想不出来" | = 缺乏自我反思，直接 fail |
| 选无关紧要的例子 | "我以为奶茶热量最高" → 太轻了 |
| 说完加"但其实我也没完全错" | = 你还是不愿意承认错了 |
| 选跟工作毫无关系的 | 面试官想看**工作中**的认知迭代 |
| 只说"我错了"没有"我怎么更新的" | 只有反思没有行动 = 不完整 |

## 六、延伸：认知迭代作为核心竞争力

### 为什么 AI 时代更需要这种能力

```
传统时代：知识 = 竞争力（你知道别人不知道的）
AI 时代 ：更新速度 = 竞争力（你能多快丢弃过时的认知）
```

### 日常练习方法

1. **记录强观点**：把自己"很确定"的判断写下来，标注日期和依据
2. **定期复盘**：每月看一遍，哪些被证伪了？为什么？
3. **寻找反证**：主动找跟自己观点相反的论据（而不是只找支持证据）
4. **量化信心**：对每个判断标注信心度（60%? 90%?），区分"我觉得"和"数据显示"
