# 📋 AI 产品需求评估框架

> 从金铲铲「以铲换X」AI 图片评分需求评估中提炼。适用于评估"是否要接入 AI 能力"的场景——快速判断可行性、风险和落地路径。

---

## 核心理念

**理解需求 → 技术验证 → 风险评估 → 交付计划**

不要先承诺后评估。用最小成本验证技术可行性，再给出有数据支撑的结论。

---

## 四步流程

### Step 1：需求理解与分类矩阵

**目标**：把模糊的业务需求转化为清晰的分类判断逻辑。

1. 收集所有需求材料（PRD、需求文档、样本数据）
2. 提炼核心判断逻辑 → 构建**分类矩阵**：
   ```
   输入 → 判断条件1 → 判断条件2 → ... → 分类结果
   ```
3. 检查每个分类的**样本充分性**：
   - ≥30 张/类：充分
   - 10-30 张/类：勉强
   - <10 张/类：⚠️ 不足，标注风险
4. 梳理**待明确事项**（QPS/展示策略/重复处理等）

### Step 2：最小成本技术验证

**目标**：用 10 张图 + 1 个 Prompt 证明可行性。

1. 每个分类选 2 张代表样本（共 ~10 张）
2. 编写纯文字评分 Prompt（不传参考图，模拟上线逻辑）
3. 逐张测试，记录结果：
   - 大类准确率（通过/不通过）→ 目标 ≥95%
   - 精确等级准确率 → 目标 ≥80%
   - ±1 级容差准确率 → 目标 ≥95%
   - 评语质量（1-5 分）
4. 分析偏差模式 → 优化 Prompt → 再测
5. 产出：验证报告（4 Tab：总览/逐张详情/偏差分析/Prompt）

> 详细验证方法参考 [[VLM视觉评分验证法]]

### Step 3：风险评估

**目标**：识别所有 P0-P2 风险，给出应对方案。

从四个维度评估风险：

| 维度 | 典型风险 |
|------|----------|
| **准确性** | 评分一致性不稳定、边界 case 误判、材质/风格偏见 |
| **性能** | 高并发（秒杀场景）、响应延迟、成本预算 |
| **合规** | UGC 内容合规兜底、未成年人保护、数据隐私 |
| **体验** | 评分争议处理、重复上传策略、失败降级方案 |

每个风险标注：
- 等级（P0/P1/P2）
- 概率（高/中/低）
- 影响（高/中/低）
- 应对方案

### Step 4：交付计划

**目标**：给出里程碑式的交付计划。

标准里程碑模板：

| 阶段 | 内容 | 周期 |
|------|------|------|
| M1 技术验证 | Prompt 优化 + 大样本验证 | 1 周 |
| M2 接口开发 | API + 数据库 + 队列 | 1-2 周 |
| M3 联调测试 | 前后端联调 + 压测 | 1 周 |
| M4 内测 | 小范围验证 + 指标监控 | 1 周 |
| M5 灰度 | 逐步放量 + A/B 测试 | 1 周 |
| M6 全量 | 上线 + 监控 + 应急预案 | 0.5 周 |

---

## 输出模板

最终评估文档应包含：

1. **结论先行**（一句话：推荐/谨慎推荐/不推荐 + 理由）
2. **分类矩阵**（核心判断逻辑）
3. **验证结果**（准确率数据 + 偏差分析）
4. **风险清单**（P0-P2 分级）
5. **待明确事项**（需业务方确认的问题）
6. **交付计划**（里程碑 + 人力 + 周期）
7. **成本估算**（API 调用成本 / 人力成本）

---

## 关键原则

| 原则 | 说明 |
|------|------|
| 🎯 结论先行 | 第一段就给"推荐/不推荐"，不要铺垫 |
| 🧪 数据说话 | 准确率/风险/成本都要有数字 |
| 📉 最小验证 | 10 张图就够判断可行性，不要全量跑 |
| ⚠️ 风险前置 | P0 风险有一个不能解决就不推荐 |
| 📊 分层推进 | 10 张→25 张→60 张→全量，逐步扩大 |

---

## 实战数据

金铲铲「以铲换X」评估结果：
- 结论：**推荐接入**，技术方案成熟
- 10 张验证：大类 100%，精确 80%，容差 100%
- 3 个 P0 风险：评分一致性 / 高并发 / 合规兜底
- 7 个待明确事项
- 交付计划：6 个里程碑，6.5 周

---

## 适用场景

- AI 图片识别/分类接入评估
- LLM 文本生成/审核接入评估
- AI 语音/视频分析接入评估
- 任何"要不要用 AI 做这件事"的决策
