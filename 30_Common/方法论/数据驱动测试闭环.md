# 🔄 数据驱动测试闭环

> 从 UC 对局复盘迭代调优中提炼。适用于 AI/算法服务的持续迭代测试，尤其是修改逻辑后需要批量验证效果的场景。

---

## 核心理念

**改代码 → 批量测试 → 数据对比 → 可视化分析 → 发现问题 → 再改代码**

不靠手动测几个 case 拍脑袋。建立自动化的测试-分析闭环，让数据告诉你改得好不好。

---

## 五步流程

### Step 1：准备测试集
- 收集**真实线上数据**作为测试集（非手造数据）
- 测试集要有代表性：覆盖各种场景/角色/段位/特殊情况
- 固定测试集不随便改，保证跨版本可比性
- 建议规模：30-50 条起步，覆盖 80%+ 的场景

### Step 2：批量自动化测试
- 编写脚本一键跑完全部测试用例：
  ```
  input（JSON/CSV）→ POST 接口 → 收集响应 → 输出 Excel
  ```
- 关键要素：
  - 输入输出都保存（可回溯）
  - 记录耗时、状态码、错误信息
  - 支持并发但不要打爆服务

### Step 3：新旧对比
- 每次修改后生成新的 result.xlsx
- 自动对比新旧结果：
  - 完全相同的跳过
  - **有变化的重点分析**：变了什么？变好还是变差？
- 输出变化摘要：N 条相同 / M 条变化 / 变化内容

### Step 4：数据分析可视化
- 对测试结果做深度分析（Plotly 交互式报告）：
  - **分布分析**：各分类/标签的频率分布
  - **覆盖率分析**：关键指标是否有数字支撑
  - **模板化检测**：输出是否高度重复/模板化
  - **异常检测**：极端值 / 空值 / 格式异常
- 产出独立 HTML 报告，可直接分享

### Step 5：反馈闭环
- 根据分析结果定位问题 → 修改代码 → 回到 Step 2
- **每轮改动只改一个变量**，便于归因
- 记录每轮改动和效果，形成迭代日志

---

## 关键原则

| 原则 | 说明 |
|------|------|
| 🔒 测试集稳定 | 不随便增删测试用例，保证可比性 |
| 🤖 一键跑完 | 脚本化，不手动测 |
| 📊 数据说话 | 不凭感觉判断效果，看数字 |
| 🔬 单变量改动 | 每次只改一处，便于归因 |
| 📝 迭代日志 | 记录每轮改了什么、效果如何 |

---

## 分析维度速查

| 分析维度 | 工具 | 产出 |
|----------|------|------|
| 分类分布 | Plotly 柱状图 | 各 label 频率 + 占比 |
| 指标覆盖率 | Python 解析 | 有无具体数字的比例 |
| 模板化程度 | 文本去重 | 重复内容占比 |
| 能力雷达 | Plotly 雷达图 | 多维能力 vs 均值 |
| 趋势变化 | Plotly 折线图 | 跨对局/跨版本趋势 |
| 新旧对比 | Diff 脚本 | 变化条数 + 变化内容 |

---

## 实战数据

UC 对局复盘迭代：
- 测试集：46 个 JSON 对局（177 个回合）
- 发现问题：93.5% 的「有待提升」无具体指标数字（模板化严重）
- label 分布：78.3% 集中在 2 个 label（脱出反打 43.5% + 防御反击 34.8%）
- subdim_behId 修复：5/46 条结果变化（改善建议命中率提升）

## 适用场景

- AI/LLM 应用迭代（复盘分析、智能客服、内容生成）
- 算法策略调优（推荐系统、搜索排序）
- 规则引擎迭代（风控规则、评分规则）
- 任何需要"改了代码验证效果"的场景
