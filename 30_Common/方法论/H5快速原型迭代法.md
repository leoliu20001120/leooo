# 🌐 H5 快速原型迭代法

> 从「异人体检站」H5 Demo 五轮迭代中提炼。适用于营销 H5、互动页面、产品 Demo 的快速落地。

---

## 核心理念

**单文件 MVP → 逐步升级 → 保持可分享**

不做过度设计，先跑起来再说。每一轮只改一个维度（结构/视觉/内容/功能），避免全量重写。

---

## 六步流程

### Step 1：PRD + Mock 数据契约
- 定义完整用户旅程（STEP 0 → STEP N）
- 撰写 Mock 数据契约（JSON Schema + 示例数据）
- **关键**：即使没有后端，也要先定义接口格式，前端按契约 Mock

### Step 2：单文件 HTML 出 MVP
- **一个 HTML 文件搞定一切**（CSS + JS 内联）
- 好处：零构建、零依赖、可直接发给任何人预览
- CDN 引入必要库（Chart.js / Plotly 等），不本地安装
- Mock 数据逻辑写在 JS 里（哈希值驱动 / 随机种子 / 状态机）

### Step 3：视觉升级
- 在 MVP 可用的基础上升级视觉
- **逐块替换**（replace_in_file），不要一次性重写整个文件
- 重点：深色主题 / 玻璃态 / 动画入场 / 字体层级 / 响应式
- 控制增量：每轮 CSS 改动控制在 50-100 行以内

### Step 4：内容升级
- 替换文案、题目、对话等内容层
- **保持代码结构不变**，只改数据和文案
- 让业务方/策划参与内容审核

### Step 5：功能迭代
- 逐个新增交互组件（Bottom Sheet / 粒子系统 / 分享等）
- 每个组件独立实现，不影响已有功能
- 新增功能必须有降级方案（加载失败不影响主流程）

### Step 6：自包含打包
- 如需分享：图片压缩 + Base64 内嵌 → 单个 HTML 可邮件发送
- 压缩策略：max 800px、JPEG Q55，通常可从 40MB+ 压到 2MB 以内

---

## 关键原则

| 原则 | 说明 |
|------|------|
| 🎯 单文件优先 | 零构建 > Webpack/Vite，降低分享门槛 |
| 🔄 逐维度升级 | 结构→视觉→内容→功能，每轮只改一个维度 |
| 📐 增量替换 | replace_in_file 逐块改，避免 token 溢出和全量重写 |
| 🧪 Mock 先行 | 先定接口契约，前端按契约 Mock，后端并行开发 |
| 📱 移动优先 | H5 主要场景是手机，响应式媒体查询（≤375px）必加 |

---

## 适用场景

- 营销活动 H5（测试类 / 互动类 / 裂变分享）
- 产品 Demo（给老板/客户看的可交互原型）
- 数据可视化报告（Plotly 交互式 HTML）
- 内部工具快速验证
