## 1. 法线基础概念速览

### 1.1 法线的三个层次

| 层次 | 说明 | 典型应用 |
|------|------|----------|
| **面法线（Face Normal）** | 三角面片的几何法线，通过两条边叉乘得到 | 平面着色（Flat Shading） |
| **顶点法线（Vertex Normal）** | 顶点处的插值法线，由相邻面法线加权平均得到 | 光滑着色（Gouraud/Phong Shading） |
| **法线贴图（Normal Map）** | 纹理像素级法线，存储在RGB贴图中 | 无需增加面数即可表现细节 |

### 1.2 法线的两种坐标空间

| 空间 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **切线空间（Tangent Space）** | 相对于模型表面局部坐标系 | 可复用、可叠加、支持变形动画 | 需要正确的切线/副切线，实现依赖烘焙工具 |
| **对象空间（Object Space）** | 相对于模型自身坐标系 | 无需切线基、精度高 | 不可复用、不支持UV动画 |

> 💡 **关键认知**：切线空间法线贴图是 **实现依赖的**（implementation dependent），不同烘焙工具生成的法线贴图 **不能通用**，必须在同一切线空间标准下烘焙和渲染。

## 2. 顶点法线计算方法及其优劣

顶点法线的计算方式直接影响模型着色的平滑度和准确度。核心思想是将该顶点相邻面的面法线做加权平均。

> **📊 图示：四种顶点法线加权方法对比**
> 
> ![[assets/normal_study/Technical_diagram_comparing_4__2026-04-04T05-38-38.png]]
> *图中展示了同一顶点在不同加权方法下的法线计算结果差异。等权方法容易被密集小三角面拉偏，面积加权受大面片主导，角度加权最接近真实曲面法线。*

### 2.1 四种主流加权方法对比

| 方法 | 公式 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|----------|
| **等权平均（Uniform）** | $\mathbf{n}_v = \text{normalize}\left(\sum_{i} \mathbf{n}_{f_i}\right)$ | 实现简单，计算快 | 小三角形与大三角形权重相同，容易偏向密集区域的法线方向 | 均匀网格 |
| **面积加权（Area Weighted）** | $\mathbf{n}_v = \text{normalize}\left(\sum_{i} A_i \cdot \mathbf{n}_{f_i}\right)$ | 大面片贡献更大，符合直觉 | 细长三角形面积大但法线方向可能不稳定 | 一般用途 |
| **角度加权（Angle Weighted）** | $\mathbf{n}_v = \text{normalize}\left(\sum_{i} \alpha_i \cdot \mathbf{n}_{f_i}\right)$ | 物理上最合理，该顶点处的角度越大贡献越大 | 计算量较大（需反三角函数） | 高质量渲染 |
| **面积+角度加权** | $\mathbf{n}_v = \text{normalize}\left(\sum_{i} A_i \cdot \alpha_i \cdot \mathbf{n}_{f_i}\right)$ | 综合考虑两个因素 | 计算最慢 | 离线高精度 |

> 📖 **学术参考**：Jin, Lewis & West (2005) *"A Comparison of Algorithms for Vertex Normal Computation"* 系统对比了上述方法，结论是 **角度加权在大多数情况下最接近真实曲面法线**。

### 2.2 具体示例：一个顶点被四个三角面共享

假设顶点 V 被四个三角面 F₁~F₄ 共享：

```
面    面法线方向      面积    顶点处角度
F₁    (0, 1, 0)     10      90°
F₂    (0, 0.7, 0.7) 2       30°
F₃    (0, 0, 1)     8       60°
F₄    (0, 0.7, 0.7) 40      180°
```

**等权平均结果**：
```
n = normalize((0,1,0) + (0,0.7,0.7) + (0,0,1) + (0,0.7,0.7))
  = normalize(0, 2.4, 2.4)
  ≈ (0, 0.707, 0.707)
```
→ F₂和F₄虽面积/角度差异巨大，但贡献相同。

**面积加权结果**：
```
n = normalize(10*(0,1,0) + 2*(0,0.7,0.7) + 8*(0,0,1) + 40*(0,0.7,0.7))
  = normalize(0, 10+1.4+0+28, 0+1.4+8+28)
  = normalize(0, 39.4, 37.4)
  ≈ (0, 0.725, 0.689)
```
→ F₄面积最大（40），显著拉偏法线方向。

**角度加权结果**：
```
n = normalize(90*(0,1,0) + 30*(0,0.7,0.7) + 60*(0,0,1) + 180*(0,0.7,0.7))
  = normalize(0, 90+21+0+126, 0+21+60+126)
  = normalize(0, 237, 207)
  ≈ (0, 0.753, 0.658)
```
→ 角度加权保持了 F₁（90°大角）的较大影响力。

### 2.3 评判顶点法线优劣的方法

| 评判方法 | 说明 | 量化指标 |
|----------|------|----------|
| **角度偏差** | 与解析曲面真实法线的夹角差 | Mean Angular Error (MAE)，单位：度 |
| **视觉一致性** | Phong着色下高光是否自然平滑 | 人眼主观评价 + 高光拉伸检查 |
| **曲面拟合度** | 法线场是否逼近原始曲面的梯度场 | 法线方向与曲面一阶导数的对齐程度 |

> 🔬 **量化示例**：对于球体（解析法线已知），角度加权平均的 MAE 通常在 **0.5°~2°**，而等权平均的 MAE 在 **2°~8°**，尤其在网格不均匀时差异更大。

## 3. 法线贴图质量的量化评估指标

### 3.1 数学/统计指标

| 指标 | 公式/说明 | 用途 | 好的阈值参考 |
|------|-----------|------|-------------|
| **均角误差（MAE）** | $\text{MAE} = \frac{1}{N}\sum_{i=1}^{N} \arccos(\mathbf{n}_i \cdot \mathbf{n}_i^{ref})$ | 评估与参考法线的整体偏差 | < 5° 优秀，< 15° 可接受 |
| **RMSE（均方根误差）** | $\text{RMSE} = \sqrt{\frac{1}{N}\sum_{i=1}^{N} \|\mathbf{n}_i - \mathbf{n}_i^{ref}\|^2}$ | 评估法线向量偏差幅度 | < 0.05 优秀 |
| **余弦相似度** | $\text{sim} = \frac{1}{N}\sum_{i=1}^{N} \mathbf{n}_i \cdot \mathbf{n}_i^{ref}$ | 方向一致性，1=完全一致 | > 0.995 优秀 |
| **角度相似度（Angular Similarity）** | 基于法线夹角的点云/网格质量度量 | 点云法线估计质量 | 值越接近1越好 |
| **法线一致性（Normal Consistency）** | 相邻像素法线夹角的平滑度分析 | 检测突变/噪声 | 梯度直方图呈单峰分布 |
| **单位长度偏差** | $\Delta = \| \|\mathbf{n}\| - 1 \|$ | 检查法线是否归一化 | = 0（严格）|

### 3.2 视觉/感知指标

| 指标 | 方法 | 示例说明 |
|------|------|----------|
| **高光测试** | 在引擎中使用高金属度+低粗糙度材质旋转观察 | 高光带是否平滑流畅，无断裂/跳变 |
| **灰度法线可视化** | 将法线映射为灰度显示各通道 | R/G通道应呈现平滑渐变，无噪点或色块 |
| **接缝检测** | 放大UV接缝区域，检查法线连续性 | 接缝处不应有亮线/暗线 |
| **法线方向可视化** | 以线段形式显示每个顶点/像素的法线方向 | 箭头方向应平滑渐变，无突变 |
| **光照旋转测试** | 使用单一方向光绕模型旋转360° | 阴影边缘过渡应自然，无锯齿或闪烁 |

### 3.3 具体示例：用角度误差评估烘焙质量

```python
import numpy as np

def evaluate_normal_quality(baked_normals, reference_normals):
    """
    评估烘焙法线贴图相对于参考法线的质量
    
    参数:
        baked_normals: shape (H, W, 3)，烘焙出的法线贴图
        reference_normals: shape (H, W, 3)，高模真实法线
    
    返回:
        dict: 包含多个质量指标
    """
    # 归一化
    baked = baked_normals / np.linalg.norm(baked_normals, axis=-1, keepdims=True)
    ref = reference_normals / np.linalg.norm(reference_normals, axis=-1, keepdims=True)
    
    # 1. 余弦相似度
    cos_sim = np.sum(baked * ref, axis=-1)
    cos_sim = np.clip(cos_sim, -1, 1)
    
    # 2. 角度误差（度）
    angle_error = np.degrees(np.arccos(cos_sim))
    
    # 3. RMSE
    rmse = np.sqrt(np.mean((baked - ref) ** 2))
    
    # 4. 归一化偏差
    norm_deviation = np.abs(np.linalg.norm(baked_normals, axis=-1) - 1.0)
    
    # 5. 法线平滑度（相邻像素角度差的标准差）
    dx = np.sum(baked[:-1,:,:] * baked[1:,:,:], axis=-1)
    dy = np.sum(baked[:,:-1,:] * baked[:,1:,:], axis=-1)
    smoothness = np.std(np.concatenate([
        np.degrees(np.arccos(np.clip(dx, -1, 1))).ravel(),
        np.degrees(np.arccos(np.clip(dy, -1, 1))).ravel()
    ]))
    
    return {
        "平均角度误差 (MAE)": f"{np.mean(angle_error):.2f}°",
        "最大角度误差": f"{np.max(angle_error):.2f}°",
        "中位角度误差": f"{np.median(angle_error):.2f}°",
        "RMSE": f"{rmse:.6f}",
        "余弦相似度 (mean)": f"{np.mean(cos_sim):.6f}",
        "归一化偏差 (max)": f"{np.max(norm_deviation):.6f}",
        "平滑度 (std)": f"{smoothness:.4f}°",
        "角度误差<5°的像素占比": f"{np.mean(angle_error < 5) * 100:.1f}%",
        "角度误差<1°的像素占比": f"{np.mean(angle_error < 1) * 100:.1f}%",
    }
```

**质量等级参考表**：

| 等级 | MAE | 余弦相似度 | RMSE | 适用场景 |
|------|-----|-----------|------|----------|
| ⭐⭐⭐ 优秀 | < 2° | > 0.999 | < 0.02 | 主角特写、电影级CG |
| ⭐⭐ 良好 | 2°~5° | 0.995~0.999 | 0.02~0.05 | 重要NPC、近距离道具 |
| ⭐ 可接受 | 5°~15° | 0.97~0.995 | 0.05~0.15 | 背景物件、远景 |
| ❌ 不合格 | > 15° | < 0.97 | > 0.15 | 需要重新烘焙 |

## 4. 法线贴图常见缺陷诊断

> **📊 图示：法线贴图 7 类常见缺陷视觉对比**
> 
> ![[assets/normal_study/Technical_comparison_diagram_o_2026-04-04T05-39-02.png]]
> *从左到右、从上到下依次为：接缝亮/暗线、凹凸反转、黑色斑块、模糊/细节丢失、色带/阶梯状、闪烁/水波纹、锯齿。识别缺陷类型是诊断的第一步。*

### 4.1 缺陷速查表

| 缺陷 | 视觉表现 | 根因 | 修复方案 |
|------|----------|------|----------|
| **接缝亮/暗线** | UV接缝处出现亮线或暗线 | ①切线空间不连续 ②Padding不足 ③硬边处理不当 | 增加Dilation至4-8px；低模优先全软边 |
| **凹凸反转** | 凸起变凹陷，或凹陷变凸起 | ①绿通道(Y)方向不匹配 ②OpenGL↔DirectX混用 | 翻转G通道；确认目标引擎格式 |
| **黑色斑块** | 部分区域全黑 | ①UV重叠 ②射线采样穿模 ③高低模对位不准 | 检查UV重叠；调整Cage/Ray Distance |
| **模糊/细节丢失** | 高模细节在低模上模糊不清 | ①分辨率不足 ②Ray Distance过大 ③过度过滤 | 提高分辨率；减小Ray Distance至0.1-0.5 |
| **色带/阶梯状** | 平滑表面出现色带渐变 | ①贴图位深不足（8bit） ②压缩质量过低 | 使用16bit/32bit烘焙；选择BC5压缩 |
| **闪烁/水波纹** | 运动时法线闪烁 | ①Mipmap层级冲突 ②采样精度不足 | 调整Mip Bias；关键贴图禁用Mipmap |
| **锯齿** | 边缘或细节处锯齿明显 | ①烘焙采样数不足 ②分辨率不匹配 | 增加Sample Rate至100+；提高分辨率 |

### 4.2 具体示例：OpenGL vs DirectX 法线格式问题

这是最常见的法线贴图问题之一：

```
OpenGL 格式（Y+）：绿通道(G) 表示朝上
   → Blender, Maya, Substance Painter (默认), Marmoset Toolbag
   
DirectX 格式（Y-）：绿通道(G) 表示朝下
   → 3ds Max, Unreal Engine (默认)
```

**诊断方法**：
1. 在纯光照下观察模型
2. 找一个明显的凸起（如螺丝头）
3. 如果光从上方照射时，螺丝头呈凹陷而非凸起 → **Y轴反了**

**修复**：
```hlsl
// Unity Shader 中翻转 Y 轴
float3 normal = tex2D(_NormalMap, uv).xyz * 2 - 1;
normal.y *= -1; // 翻转绿通道
```

### 4.3 具体示例：UNORM 解包精度陷阱

这是一个极易被忽视的技术细节：

```
标准解包公式：normal.xy = 2.0 * texColor.xy - 1.0

问题：8bit 纹理中值 128/255 = 0.50196
      代入：2.0 * 0.50196 - 1.0 = 0.00392 ≠ 0.0

后果：本应指向正上方的 (0,0,1) 法线实际变成了 (0.00392, 0.00392, ~1.0)
      在 UV 接缝处因切线空间旋转方向不同而产生可见的亮/暗线
```

**修复**：
```hlsl
// 方案A：调整解包偏移
normal.xy = 2.0 * texColor.xy - (254.0 / 255.0);

// 方案B：使用 SNORM 格式纹理（硬件自动处理）
// 在引擎/工具中将法线贴图标记为 SNORM 而非 UNORM
```

## 5. 切线空间与MikkTSpace标准

### 5.1 为什么切线空间很重要

> **核心问题**：切线空间法线贴图是 **实现依赖的**。每个烘焙工具使用不同的切线空间算法，导致同一张法线贴图在不同渲染器中可能产生不同结果。

**经典错误**：
- 用 xNormal 烘焙法线 → 导入 Unreal Engine → **光照结果不对**
- 原因：xNormal 和 UE 使用不同的切线空间实现

### 5.2 MikkTSpace 标准

MikkTSpace（由 Morten Mikkelsen 开发）已成为业界事实标准，旨在解决切线空间不一致的问题。

| 特征 | 说明 |
|------|------|
| **目标** | 统一切线空间计算，使烘焙结果可在不同工具间通用 |
| **支持引擎** | Unreal Engine, Unity, Godot, Three.js 等主流引擎 |
| **支持烘焙工具** | Substance Painter, Marmoset Toolbag, Blender（2.57+） |
| **核心算法** | 基于三角形的UV和位置信息计算每个顶点的切线和副切线 |
| **关键要求** | 烘焙工具和渲染引擎 **必须使用相同的 MikkTSpace 实现** |

### 5.3 同步工作流（Synced Workflow）评判标准

| 检查项 | 合格标准 | 不合格后果 |
|--------|----------|------------|
| 烘焙器切线空间 = 渲染器切线空间 | 必须一致（如都用MikkTSpace） | UV接缝处出现亮/暗缝隙 |
| 法线贴图格式（OpenGL/DirectX） | 必须与目标引擎匹配 | 凹凸方向反转 |
| 平滑组/硬边设置 | 烘焙时与渲染时一致 | 硬边处产生错误着色 |
| UV布局 | 烘焙后不可修改UV | 法线方向完全错乱 |

> **📊 图示：切线空间同步 vs 不同步工作流效果对比**
> 
> ![[assets/normal_study/Technical_diagram_showing_Sync_2026-04-04T05-40-19.png]]
> *左侧同步工作流（烘焙器和渲染器都使用 MikkTSpace）：UV 接缝处平滑无瑕。右侧不同步工作流：UV 接缝处出现明显的亮线和高光偏移。*

**具体示例**：同步 vs 不同步的视觉差异
```
✅ 同步工作流（Substance Painter → UE5，都用 MikkTSpace）:
   - UV接缝处平滑过渡
   - 高光连续无断裂
   - 平面区域法线精确指向 (0,0,1)

❌ 不同步工作流（xNormal → UE5）:
   - UV接缝处出现细微亮线
   - 高光在接缝处偏移
   - 平面区域法线略有偏差
```

## 6. 法线贴图压缩格式质量对比

### 6.1 主流压缩格式对比

| 格式 | 平台 | 存储方式 | bpp | 有效精度 | 质量评级 | 备注 |
|------|------|----------|-----|----------|----------|------|
| **BC5** | PC/主机 | 双通道独立（XY） | 8 | ~10-11 bit | ⭐⭐⭐ | **PC首选**，平滑区域表现最佳 |
| **BC3/DXT5** | PC（旧） | RGB+Alpha（XY重排） | 8 | ~5-6 bit (X), ~8 bit (Y) | ⭐ | 已过时，色带严重 |
| **EAC_RG** | 移动端 | 双通道独立 | 8 | 略高于BC5 | ⭐⭐ | 统计误差低但感知质量不如BC5 |
| **ASTC 4×4** | 移动端 | 自适应 | 8 | 取决于编码 | ⭐⭐⭐* | 理论最高质量，但需特殊编码支持 |
| **ASTC 6×6** | 移动端 | 自适应 | 3.56 | 较低 | ⭐⭐ | 压缩率更高，质量降低 |
| **无压缩 (RGBA8)** | 全平台 | 四通道完整 | 32 | 8 bit | 参考基线 | 64MB/4K贴图，仅用于离线 |
| **无压缩 (RGBA16)** | 全平台 | 四通道完整 | 64 | 16 bit | 黄金标准 | 128MB/4K贴图，离线高质量 |

> ⚠️ **重要发现**（2026年 Ignacio Castaño 研究）：EAC_RG 的 RMSE 数值实际上低于 BC5，但在 **人眼最敏感的平滑区域**，BC5 的视觉质量反而更高。这说明 **统计指标不能完全替代视觉评估**。

### 6.2 Z 分量重建的质量影响

BC5 和 EAC_RG 都只存储 X、Y 两个分量，Z 需要在着色器中重建：

```hlsl
// Z 分量重建
float z = sqrt(1.0 - saturate(dot(normal.xy, normal.xy)));
```

> **📊 图示：Z 分量重建的误差放大效应**
> 
> ![[assets/normal_study/Technical_diagram_of_Z_compone_2026-04-04T05-40-12.png]]
> *单位半球上，顶部法线（接近垂直）的 Z 重建误差很小（~0.1%），但边缘法线（接近平躺/掠射角）的 Z 重建误差可被放大到 22% 以上。半球表面颜色越红表示误差越大。*

**质量影响分析**：
- 正交投影只利用了约 **86%** 的 XY 值域（单位圆 vs 正方形）
- 超出单位圆的值需要钳位（clamp），引入误差
- 压缩误差会被放大：XY 的微小误差通过 sqrt 传播到 Z

**具体示例**：压缩误差对 Z 分量的影响
```
原始法线:   (0.5, 0.5, 0.707)  → |n| = 1.0
压缩后 XY:  (0.502, 0.498)     → 微小量化误差
重建 Z:     sqrt(1 - 0.502² - 0.498²) = sqrt(1 - 0.252 - 0.248) = sqrt(0.500) = 0.707
→ 此情况下误差可忽略

原始法线:   (0.95, 0.3, 0.0707) → 接近"平躺"的法线
压缩后 XY:  (0.953, 0.298)      → 同样微小误差
重建 Z:     sqrt(1 - 0.953² - 0.298²) = sqrt(1 - 0.908 - 0.089) = sqrt(0.003) = 0.055
实际 Z:     0.0707
误差:       |0.055 - 0.0707| / 0.0707 = 22.2% 相对误差！
→ 接近"平躺"的法线对压缩误差极其敏感
```

## 7. 实战评判清单

### 7.1 法线贴图质量快速检查（适用于游戏开发日常）

```
□ 1. 格式检查
  □ 贴图格式正确（OpenGL/DirectX 与引擎匹配）
  □ 使用推荐压缩格式（PC: BC5, 移动: EAC_RG/ASTC 4×4）
  □ 位深足够（烘焙用 16bit，运行时可压缩）

□ 2. 视觉检查
  □ 高光测试：金属球材质旋转360°，高光连续无断裂
  □ 接缝检查：UV接缝处无亮/暗线
  □ 凹凸方向：凸起/凹陷方向正确
  □ 细节保真：高模细节在低模上清晰可辨
  □ 平面检查：应该平坦的区域确实是纯蓝色 (128, 128, 255)

□ 3. 工作流检查
  □ 切线空间同步：烘焙器与渲染器使用相同切线空间标准
  □ 平滑组一致：烘焙与渲染时平滑组设置一致
  □ UV未修改：烘焙后未改动UV
  □ Padding足够：至少4像素的Dilation

□ 4. 性能检查
  □ 分辨率分级：主角4K/NPC 2K/道具1K/背景512
  □ 压缩格式：无未压缩的法线贴图残留
  □ Mipmap：已生成（除非有特殊锐度需求）
```

### 7.2 法线计算方法选择决策树

```
你的应用场景是什么？
│
├─ 实时游戏渲染
│  ├─ 网格是否均匀？
│  │  ├─ 是 → 等权平均（性能最优）
│  │  └─ 否 → 角度加权（质量最优）
│  └─ 是否有大量硬边？
│     └─ 是 → 使用平滑组/硬边分割 + 角度加权
│
├─ 离线电影级渲染
│  └─ 面积+角度混合加权（质量优先）
│
├─ 科学计算/仿真（CAE）
│  └─ 面积加权（与有限元分析兼容）
│
└─ 点云法线估计
   ├─ 噪声大？→ 鲁棒法线估计（PCA + 去噪）
   └─ 精度优先？→ 混合角度-欧氏距离编码（HAE方法, CVPR 2025）
```

### 7.3 法线贴图缺陷诊断决策树

```
你看到了什么问题？
│
├─ 凹凸方向反了
│  └─ 翻转绿通道(G)或切换 OpenGL↔DirectX 格式
│
├─ UV接缝处有亮/暗线
│  ├─ 切线空间不同步？→ 统一使用MikkTSpace
│  ├─ Padding不足？→ 增加Dilation至4-8px
│  └─ UNORM精度问题？→ 调整解包偏移或使用SNORM
│
├─ 黑色区域
│  ├─ UV重叠？→ 展UV确保无重叠
│  └─ 射线穿模？→ 调整Cage/Ray Distance
│
├─ 细节模糊
│  ├─ 分辨率不足？→ 提高分辨率
│  └─ Ray Distance过大？→ 减小至0.1-0.5
│
├─ 色带/渐变不连续
│  ├─ 8bit精度不足？→ 使用16bit
│  └─ 压缩质量低？→ 使用BC5替代DXT5
│
└─ 运动时闪烁
   ├─ Mipmap冲突？→ 调整Mip Bias
   └─ 动画变形？→ 启用 "Preserve Tangents"
```
