# Claude Code 源码泄露事件深度调研（2026.3.31）

> 调研日期：2026-04-03
> 标签：#AI调研 #Claude_Code #源码泄露 #未发布功能 #AI产品设计
> 来源：WaveSpeed.ai / 36kr / TheNewStack / AgenticMarket / VentureBeat / ClawDecode 等多源交叉验证

## 📋 执行摘要

2026年3月31日，Anthropic 旗下 AI 编程工具 Claude Code v2.1.88 因 npm 发布时误包含 source map 文件，导致约 **51.2万行 TypeScript 源码**（1,900个文件）完整泄露。泄露内容包括 **44个 feature flags**（至少20个锁定已构建但未发布功能）、**43个工具**、**7大隐藏功能系统**，以及内部模型代号和性能基准数据。

**核心发现**：Claude Code 不是一个编程助手，而是一个**完整的 AI 代理操作系统**，正在从"被动响应式工具"向"主动式 AI 合作伙伴"演进。

---

## 一、事件始末

### 1.1 泄露原因
- **直接原因**：发布 v2.1.88 时，构建管道配置错误，将 59.8MB 的 `.map`（source map）文件打包进了公开的 npm 包
- **发现者**：安全研究员 Chaofan Shou 在 X 平台首先披露
- **时间线**：Anthropic 在数小时内撤下包，但镜像已在 GitHub 广泛传播（备份库 7 小时获 2w+ 星标）
- **讽刺之处**：这是 Claude Code 第二次因 source map 泄露（2025年2月首发时也泄露过一次），同款错误犯了两次

### 1.2 泄露范围
| 维度 | 数据 |
|------|------|
| 代码行数 | ~512,000 行 TypeScript |
| 文件数 | 1,900 个 |
| Feature Flags | 44 个（编译时特性开关） |
| 工具数 | 43 个 |
| 隐藏环境变量 | 120+ 个 |
| 远程控制开关 | 200+ 个 |

### 1.3 核心模型是否泄露？
**否**。模型权重、训练数据均未泄露。泄露的是产品层代码（架构、功能逻辑、编排策略），不是模型层。但**产品路线图已完全公开**。

## 二、8大未发布功能详解

### 2.1 🐣 BUDDY — 虚拟宠物系统

| 维度 | 详情 |
|------|------|
| **定义** | 嵌入终端的 ASCII 虚拟伙伴，类似电子鸡 |
| **物种** | 18种（鸭子/龙/水豚/蘑菇/幽灵/仙人掌/机器人等） |
| **稀有度** | 5级：普通(60%) → 少见(25%) → 稀有(10%) → 史诗(4%) → 传奇(1%) |
| **属性** | 5项：DEBUGGING / PATIENCE / CHAOS / WISDOM / SNARK |
| **生成机制** | 基于 `hash(userId)` **确定性生成**，同一用户永远获得同一宠物 |
| **灵魂生成** | 名字和性格由 Claude 首次孵化时 AI 生成 |
| **装饰** | 可佩戴帽子 |
| **预计发布** | 4月1-7日预告，5月正式发布（代码注释） |

**💡 功能价值**：
- **情感连接**：将冷冰冰的 CLI 工具转化为有"陪伴感"的体验
- **用户粘性**：稀有度系统 + 独一无二的宠物 → 用户不愿切换工具
- **品牌人格化**：从"AI工具"到"AI伙伴"的心智转变

### 2.2 🧠 KAIROS — 始终在线的主动助手

| 维度 | 详情 |
|------|------|
| **定义** | 持久化后台守护进程模式，不需要用户提示即可主动工作 |
| **核心机制** | 接收周期性 `<tick>` 提示，自主决定采取行动还是保持静默 |
| **执行预算** | 15秒阻塞预算，确保不长时间中断开发者工作流 |
| **输出模式** | 使用"Brief"模式提供简洁响应，避免终端信息淹没 |
| **源码引用** | 超过 150 次引用 |
| **当前状态** | Feature flag 完全封锁，已编译但未发布 |

**💡 功能价值**：
- **范式转换**：从"你问我答"→"我主动帮你"，AI 从工具变为合作伙伴
- **上下文积累**：随时间推移建立对用户工作的深层理解
- **行业领先**：开源框架（CrewAI/LangGraph/Google ADK）均无可比功能

### 2.3 💤 autoDream — 记忆整理服务（KAIROS 子系统）

| 维度 | 详情 |
|------|------|
| **定义** | 空闲时自动执行的记忆整合服务 |
| **四阶段流程** | ① Orient（定向：读索引）→ ② Gather（收集：检查日志）→ ③ Consolidate（整合：合并新旧、消除矛盾）→ ④ Prune（修剪：保持索引≤25KB） |
| **核心能力** | 合并跨会话观察、消除逻辑矛盾、将临时笔记转为确认事实、转换相对日期为绝对日期 |

**💡 功能价值**：
- **类比**：相当于操作系统的垃圾回收器，但针对的是 AI 的知识
- **实用性**：解决长期使用中记忆退化/矛盾问题

### 2.4 📋 ULTRAPLAN — 云端深度规划

| 维度 | 详情 |
|------|------|
| **定义** | 将复杂任务规划卸载到云端 Opus 4.6 模型 |
| **规划时长** | 最长 30 分钟 |
| **用户界面** | 提供浏览器界面监控，执行前需用户批准计划 |

**💡 功能价值**：
- **复杂任务处理**：用更强模型 + 更长时间思考 → 更高质量的规划
- **人机协同**：不是全自动，而是"AI规划 + 人类审批"

### 2.5 🤝 Coordinator Mode — 多 Agent 协调

| 维度 | 详情 |
|------|------|
| **定义** | 一个 Claude 实例充当"协调器"，管理多个并行"工作代理" |
| **通信方式** | 邮箱系统（Unix Domain Sockets / Bridge 协议） |
| **安全机制** | 子代理只能拥有父级权限的子集，无法提权 |
| **角色系统** | 基于角色（只读代理如 Explore/Plan 物理上无法破坏代码） |
| **内存同步** | 团队内存同步机制协调各代理 |

**💡 功能价值**：
- **效率倍增**：并行处理子任务，处理效率提升 3 倍以上
- **安全隔离**：能力安全模型（Capability-based Security），子代理权限最小化
- **行业趋同**：与 CrewAI/Google ADK/LangGraph 模式趋同，但安全性更优

### 2.6 🕵️ Undercover Mode — 卧底模式

| 维度 | 详情 |
|------|------|
| **触发条件** | Anthropic 员工 + 操作非内部仓库时自动激活 |
| **行为** | 剥离 `Co-Authored-By`、隐藏模型代号、伪装为人类提交 |
| **关闭选项** | **无强制关闭开关**，安全默认开启 |
| **争议** | 违反开源协作中 AI 参与度披露规范 |

**💡 功能价值/争议**：
- 保护商业秘密 vs 开源透明度的矛盾
- 揭示行业真实状态：大量开源贡献可能已有 AI 辅助但未披露

## 三、核心架构洞察

### 3.1 MCP 不是插件系统，MCP 就是产品本身

> Claude Code 的所有功能（文件读取、Bash执行、Web获取、LSP集成）都通过 MCP 标准接口暴露。

- 基础工具定义：29,000 行
- 所有工具遵循 MCP 规范：`tools/list` 发现 + `tools/call` 调用
- Computer Use 实际上是一个 MCP 服务器（`@ant/computer-use-mcp`）
- **启示**：MCP 正在成为 AI 代理的通用接口标准

### 3.2 三层记忆架构

```
MEMORY.md (索引层)     → 始终在上下文中，~150字/行的短指针
    ↓
主题文件 (知识层)       → 按需加载，实际的项目知识
    ↓  
原始记录 (存档层)       → 永不完整重读，仅按标识符搜索
```

**核心原则**："怀疑式记忆"——不信任自己记得写下的内容，根据磁盘实际内容验证。

### 3.3 六级安全架构

1. 六级权限验证（每次工具调用必经）
2. 四层决策管道
3. 独立沙箱环境
4. 非阻塞缓冲区处理
5. 智能上下文压缩（token 超阈值自动压缩）
6. 负面情绪检测（正则匹配关键词）

### 3.4 运行时选择

- **Bun** 而非 Node.js → 优化性能和启动速度
- **React + Ink** → 终端 UI 框架
- 查询引擎核心：~46,000 行代码

### 3.5 内部模型代号

| 代号 | 对应模型 | 备注 |
|------|----------|------|
| Capybara | Claude 4.6 变体 | 虚假声明率 29-30%（v4 为 16.7%） |
| Fennec | Opus 4.6 | 用于 ULTRAPLAN |
| Numbat | 未发布模型 | 仍在测试中 |

### 3.6 反蒸馏机制

源码包含 `ANTI_DISTILLATION_CC` 标志：启用时在 API 请求中注入虚假工具定义，旨在腐蚀试图从 API 流量中提取训练数据的行为。

## 六、Anthropic 内部开发规范（泄露）

Claude Code **内部版本**对 Anthropic 员工有更严格的约束：

| 规则 | 内容 |
|------|------|
| 工具调用间回复 | ≤ 25 字 |
| 最终回复 | ≤ 100 字 |
| 代码注释 | 默认不写，除非原因不明显 |
| 多文件编辑 | 编辑 ≥3 个文件时强制验证代理 |

**启示**：Anthropic 内部追求"简洁 + 高信号"的 AI 交互模式，认为冗长输出是 AI 工具的常见病。

## 七、关键启发与思考

### 7.1 AI 产品设计启发

1. **情感连接是竞争护城河**：BUDDY 证明技术领先者也在投资"人格化"
2. **主动式 AI > 被动式 AI**：KAIROS 是从"工具"到"同事"的跨越
3. **记忆系统是核心竞争力**：不是 RAG/向量数据库，而是简单的 Markdown + 索引
4. **安全是功能，不是约束**：六级验证不是障碍，而是产品卖点
5. **MCP 统一一切**：连 Computer Use 都是 MCP 服务器，协议标准化的彻底程度

### 7.2 值得深入思考的问题

1. 游戏 AI NPC 是否可以借鉴 BUDDY 的"确定性宠物生成"机制？
2. AI Coach 是否应该像 KAIROS 一样"主动推送建议"而非等用户询问？
3. 多 Agent 协调模式如何应用于复杂的对局分析？
4. autoDream 的记忆整理机制是否可以用于 AI NPC 的长期记忆管理？
